## Question

前置依据：[Cargo 语义研究](0078-research-cargo-package-semantics.md)、[Zig 分工研究](0079-research-zig-package-semantics.md)。

在“同一包可同时提供导入模块和可执行产物”的已定方向下，怎样表达提供方身份、导出名称、入口与默认值，才能让最小声明简洁又不产生隐式歧义？

需定清：包可以提供几个导入模块/程序；包名与导出名/程序名是否有默认关系；哪些入口可约定发现、如何显式关闭或覆盖；同名或多候选入口如何失败；旧包级 LIB/BIN 与内部 Effective_Target 的概念如何重新定位。Jai 的导入模块与二进制库不能混用，编译平台 target 也不是这里的产物。

用只提供模块、只提供程序、模块加程序、多个程序、空包/纯组织根的具体例子逐项定规则。完成条件：概念关系与基数、候选字段及默认/冲突矩阵足够明确，依赖选择和工作区选包讨论无需猜测。本票只决策，不改实现。

## Comments

### 第一轮：能力与默认模式

用户对本轮四项推荐明确回复“按推荐”：

1. 一个包可提供零个或多个公开导入模块、零个或多个可执行程序；各自有名称和入口，不因产物类别强制拆包。
2. 未配置时仅按少量固定入口推断；显式配置后只使用清单，不额外追加发现项；可以明确关闭发现。具体入口路径、分类独立性及 Jai 字段表达尚未决定。
3. 没有公开模块和程序的包仍合法，例如测试专用包；仅组织成员的根目录使用独立工作区，不必伪造包身份。
4. 本轮不新增静态/动态二进制库产物声明；导入模块不等同于二进制库，链接和导出符号规则留给独立 effort。

第一轮结束时本票保持开放，以上是阶段共识，不是完整 Resolution。

### 第二轮：分类发现、入口与命名

用户对本轮四项推荐明确回复“按推荐”：

5. 模块与程序分别选择自动发现、显式清单或关闭，互不影响；显式配置程序不会强制重复声明默认模块。
6. 模块自动候选仅为包根 `module.jai` 与 `src/module.jai`：恰有一个则采用，两个都存在时报错；程序自动候选仅为 `src/main.jai`，不递归扫描。缺少候选时得到零项。显式清单模式不检查该类别的自动候选冲突，其他布局只能显式声明。
7. 自动发现的名称默认取包名，不更改大小写。显式项必须给入口；单项可省略名称并取包名，多项必须逐项命名，不根据文件名或目录名推断。
8. 模块与程序分属不同命名类别，可以跨类别同名；同一类别重名一律失败，仅大小写不同也视为重名，避免平台差异。具体合法字符及 Unicode 判重算法交声明校验票。

第二轮结束时本票保持开放；程序默认运行选择交命令选包票，不在本票暗定。

### 第三轮：空清单、路径与字段职责

用户对 Q9–Q12 明确回复“按推荐”：确认显式空清单关闭发现、入口以包根为基准且必须为包内现存 `.jai` 文件、同类规范化入口去重，以及 `modules` / `executables` 与单项 `name` / `entry` 的职责。三轮决定统一记录于下方 Resolution；具体 Jai 类型表达仍由后续声明校验票处理。

## Resolution

本票的提供方声明模型已由用户三轮确认；仅完成设计决定，尚未修改产品代码。下列规则是后续票的输入，不把实现命名或未决定的命令行为混入其中。

### 1. 包与公开能力

- 包是身份与组织单位，可以有零个或多个公开导入模块、零个或多个可执行程序，两类能力可以并存。
- 包级 `type` 不再用 LIB/BIN 二选一限制能力；公开声明按 `modules` 和 `executables` 分开表达，不继续用泛化的 `targets` 代替这两类职责。
- 导入模块是源码导入接口，不是需要链接的二进制库。本轮不新增静态库、动态库的产物声明。
- 没有公开模块和程序的包仍合法，例如测试专用包；只组织成员的根目录可使用独立工作区而不声明根包。
- “包声明合法”不预先决定 `build` / `run` / `test` 遇到零产物时成功、提示还是报错；该问题明确交接到命令选包票。

### 2. 两类声明独立选择发现模式

| 类别配置的语义状态 | 规则 |
|---|---|
| 省略 | 只检查该类别的固定自动入口 |
| 显式非空清单 | 只采用列出的项，不追加自动发现项，也不检查该类别未采用的自动候选是否冲突 |
| 显式空清单 | 该类别为零项，关闭自动发现 |

模块与程序分别选择上述状态，互不改变对方的模式。“关闭”已有明确语义，但是否还需要独立于空清单的写法、怎样在 Jai 中区分省略与空数组，由声明校验票选择，不在此假定零初始化数组足够表达。

### 3. 自动入口与名称

- 模块候选仅有包根 `module.jai`、`src/module.jai`。零候选得到零模块；恰有一个则采用；两者都存在时报歧义错误，不按目录优先级选择。
- 程序候选仅有 `src/main.jai`，不存在则得到零程序；不递归扫描 `src/bin` 或其他文件。
- 自动发现的模块和程序默认名称均为包名，不改大小写，也不从文件名推导公开名称。其他布局只能显式指定入口。
- 默认名称仍须符合后续校验票确定的名称规则；本票没有承诺对非法名称做隐式转换。

### 4. 显式项的职责

| 字段 | 已定语义 |
|---|---|
| `modules` | 模块提供清单；每项的 `name` 是提供方导出名 |
| `executables` | 可执行程序清单；每项的 `name` 是程序名 |
| `entry` | 每个显式项必填的源码入口 |
| `name` | 显式清单恰有一项时可省略并取包名；有多项时逐项必填 |

程序名和模块导出名不是包身份，也不是依赖消费方的导入别名。同包模块与程序之间的引用方式、消费方选择一个或多个导出的规则由依赖票决定；声明多个模块不等于自动将它们全部注入每个消费者。

### 5. 路径、重复与失败规则

- 入口以声明所属包根为基准解析，必须指向包内现存的 `.jai` 文件。显式入口无效或不存在时直接失败，不回退到默认文件。
- 跨包代码通过依赖引用。生成文件的接入方式、存在性检查与生成阶段的关系由构建定制票另行决定，不能默默放宽普通源码入口规则。
- 名称按类别判重：模块和程序可以同名；同类名称重复或只在大小写上有差别均失败，不以声明顺序决定胜者。
- 同一类别不能以不同名称重复声明同一个规范化入口路径；跨类别不额外禁止共用同一个入口。能否作为对应类别编译仍须通过 Jai 检查，声明许可不保证编译成功。
- 路径规范化、符号链接/大小写别名、名称合法字符、Unicode 比较及具体错误阶段由声明校验票定义算法，但不得消除以上错误语义或引入隐式回退。

### 6. 组合验收表

以下 `省略`、`[]` 和 `{ name, entry }` 仅表示语义数据，不是已经验证的 Jai 类型写法。包名均为 `codec`，列出的入口除注明外均存在。

| 场景 | 预期结果 |
|---|---|
| 两类配置省略，只有 `src/module.jai` | 模块 `codec`，无程序 |
| 两类配置省略，只有 `src/main.jai` | 程序 `codec`，无模块 |
| 两类配置省略，同时有 `src/module.jai`、`src/main.jai` | 模块 `codec` 与程序 `codec`，跨类别同名合法 |
| 两类配置省略，没有固定候选入口 | 两类均为零，包声明仍合法 |
| 模块配置省略，同时有 `module.jai`、`src/module.jai` | 模块入口歧义错误 |
| 模块显式指定 `src/module.jai`，两个自动候选均存在 | 只采用显式项，不因未使用候选冲突而失败 |
| 模块配置省略；程序显式列出 `serve`、`admin` 及各自入口；另有 `src/main.jai` | 保留模块自动发现；仅生成两个声明的程序，不追加第三个程序 |
| `modules = []`、`executables = []`，默认文件仍存在 | 无公开模块和程序，声明合法 |
| `modules = [{ entry = "api/codec.jai" }]` | 唯一模块名默认为 `codec` |
| 一个类别显式列出多项，其中任一项缺 `name` | 名称缺失错误，不取文件名或自动编号 |
| 显式项入口缺失或越出包根，同时存在有效默认入口 | 显式入口错误，不回退 |
| 同类两项名称为 `Codec` 与 `codec` | 同类名称冲突 |
| 同类不同名项使用 `src/module.jai` 与 `src/./module.jai` | 规范化后入口重复，失败 |
| 模块和程序各用同一名称、同一入口文件 | 不因跨类别重复拒绝；各自仍受编译有效性约束 |
| 根目录只组织成员，无根包身份 | 由独立工作区模型表达；不伪造空根包 |
