## Question

在 [包与产物模型](0080-decision-package-products-defaults.md)、[依赖解析](0081-decision-dependency-identity-sources.md)、[工作区选包](0082-decision-workspace-members-selection.md#resolution) 和 [插件及构建定制分工](0083-decision-plugins-build-customization.md) 定清后统一校验契约。

已选概念如何形成一份可在 Jai 中可靠表达的声明契约，区分用户输入、规范化结果和运行时状态，并让默认值、互斥条件与错误可预测？

需确定 package.jai 的公开入口与包/工作区联合表达；字段的必填/可省略/明确为空区别；默认推断与显式声明优先级；来源等互斥选项怎样避免不可表达或非法状态；声明求值允许什么计算及副作用、失败发生在哪个阶段；版本/名称/路径/重复值/未知或暂不支持字段的错误。加载器回填的 dir 等状态不能在未决情况下继续混入用户声明面。

[提供方模型的决定](0080-decision-package-products-defaults.md#resolution) 已确定 modules/executables 与 name/entry 的职责。本票须在 Jai 中可靠区分“省略=自动”与“显式空清单=关闭”，不能依赖普通空数组零初始化来猜用户意图；确定三态是否有独立模式类型及无效组合。还需落实名称大小写等价、合法字符/Unicode、入口规范化、包内包含关系和符号链接/大小写别名处理；明确默认包名不合法时的错误，而非隐式改写名称。生成入口的检查阶段遵循构建定制票。内部 Effective_Target 等规范化结果不再代表互斥包类型；具体内部结构命名不必暴露给清单作者。

依赖的完整语义与失败矩阵见 [依赖解析决定](0081-decision-dependency-identity-sources.md#resolution)；下文是本票待落实的表达与算法交接，不替代该统一契约。需分别表达 Dependency.name/source/modules 与选择项 path/name/alias，并区分依赖 modules 省略（来源根唯一模块简写）与显式空列表（不引用模块）。选择项 path 省略为来源根，不同于本地 source.path 相对声明包根的定位基准；模块导出 entry 不由消费方覆盖。引用配置与提供方 modules 虽同名但职责不同，最终类型和错误说明必须区分。依赖选择项 name 省略时采用目标包唯一模块，零模块与多模块分别报错；最终 alias/导出名在消费包内统一判重，完全重复引用不默默合并。modules[].path 禁止绝对路径与规范化后越出来源根；细化路径与大小写算法不得改变已定失败语义。

依赖讨论第九轮进一步要求：同一消费包对同一实际模块的重复选择必须报错，即使 alias 不同；提供方包内模块/依赖不能直接泄漏为消费方可见模块。需给出来源与模块同一性、包内导入范围的可验证表达，不能仅凭全局搜索目录推定已经隔离。普通依赖的显式空模块列表须报能力不匹配。Git 已解析提交属于本机解析状态，第十三轮已明确它与可删除的源码内容缓存分目录保存；它不是用户清单字段，也不是本轮要引入的可提交锁文件；提供方身份从目标清单取得，不再另设 package 名称断言；普通依赖不做包版本范围求解，Git tag 不与清单包版本自动校验。最终依赖导入名不能与本包模块或编译器标准模块冲突，消费者可显式 alias 重命名；不自动生成别名或覆盖。包级直接依赖图须检测环并报告完整环路。同一实际模块按规范化来源/修订、包目录和导出身份判重，不以 Dependency.name/alias 判断；依赖解析记录须同时区分发起解析的工程上下文、声明包及来源选择器，不能仅用全局源码缓存的物理目录作选择记录键。同名但来源或提交不同的包允许在显式引用名/别名区分后并存；最终同一实际模块仍报重复。缓存选择键、路径规范化及后续编译适配须保持这一隔离范围。

缓存与状态基目录遵循依赖讨论第十三轮的 XDG/平台默认矩阵。需落实平台绝对路径判定、相对 XDG 值警告并回退、可靠默认用户目录取得及创建/写入错误；有效配置不可写时不得偷偷换目录，无法取得默认目录时不得写到 cwd、系统根或临时目录。解析上下文根规范化也须支持“工程移动为新上下文、源码缓存清理不清除选择状态”的已定行为。

依赖讨论第十四轮确认：引用名/别名/模块选择变化不得改变既有 Git 提交；解析选择状态仅在完整依赖图通过获取、清单、选择、冲突与环校验后整体提交，失败保留旧状态但本次操作失败。损坏或不可读状态不能被当作缺失重建。离线无记录时只有完整 rev 且全部必要内容已缓存才可建立选择；浮动/短修订无记录、内容缺失和要求刷新远端均须报错。具体状态编码、原子提交及并发保护可以统一设计，但不得弱化这些行为。

依赖讨论第十五轮要求本地 path/workspace 先各自校验定位/成员资格，再按最终规范化包目录及导出判定同一模块；不得把来源写法差异当成重复选择的豁免。不同包名或同一 Git HEAD 不能取代路径/来源身份算法。外部 Git 包的 workspace 归属不得搜索到检出外或消费工程，具体工作区算法由工作区票提供。Git 包内部 path 的目标也必须位于同一检出，保留仓库/提交身份，不因相对路径访问就退化为任意本地来源；应验证包含关系与来源身份继承。另须明确 Git URL、branch/tag/rev 和完整/短修订的具体合法格式及错误，不能暗加包版本范围求解。

工作区语义与组合表见 [工作区选包决定](0082-decision-workspace-members-selection.md#resolution)。本票须落实包/工作区各自可选并可共存的可靠表达；区分未声明工作区与声明空工作区，default_members 省略/显式空/非空，以及可选 default_run。工作区成员的去重与同名包的选择歧义不能沿用“所有重复均报错”的依赖模块规则。还需定义单层 `*`、目录子树排除、规范化后的归属/包含判断、稳定路径排序和包名/程序名的匹配算法；拒绝绝对或越界路径，保留内层工作区与 Git 检出查找边界。明确整工作区声明校验、完整选包校验及仅所选包依赖获取/执行的阶段，生成入口按构建定制票衔接；不能为校验未选成员而隐式获取其无关远程依赖。向上定位、测试扫描遇下级 package.jai 即停止及失败不回退须形成可验证的错误案例。具体 CLI 已由该票确定，不再另选一套更新/选包入口。

完成条件：字段表、归一化与校验顺序、错误案例、最小 Jai 声明草案均可交接；不在本票实施求值器或重构结构体。

## Comments

以下保留逐轮确认及用户修订；Q25 的最终嵌套 Package 写法替代早期公开 Manifest/Some 提案，内部三态语义仍有效。已撤回的重复提案不再作为待确认问题保留。

### 第一轮：Manifest 入口、三态表达与校验阶段

用户答复：`全部按推荐`，确认 Q1–Q5。

- `package.jai` 使用唯一的公开 `PACKAGE :: Package.{...}` 入口；包身份字段与 `workspace` 字段可分别出现并可共存。用户配置不增加 `Manifest`、`Some` 或其他可选值包装。只有 workspace 字段的声明表示纯工作区；两者都没有是声明错误。
- 所有需要区分省略与显式空的列表使用显式三态，不用 Jai 普通数组零值猜测：省略为 AUTO，显式空为 EXPLICIT_EMPTY，非空为 EXPLICIT_VALUES。适用于 modules、executables、plugins；default_members 也区分省略、显式空和非空，但其 AUTO 语义按工作区默认选包规则解释。
- 保留 Jai 的声明求值能力，但声明契约只承认最终 Manifest 数据。允许字面量、常量、数组/结构体构造和受限编译期表达式；文件写入、网络、进程、环境探测等副作用不属于声明接口。求值失败、返回值类型/结构不合法分别在声明求值或结构校验阶段失败；构建脚本和插件不在声明求值阶段执行。
- 路径和名称先规范化再严格校验：拒绝绝对或越界路径，不以大小写、空白、非法字符或 Unicode 改写输入，不以自动入口回退掩盖显式非法值；符号链接不能绕过包根。具体比较算法和字符集由后续轮次落实。
- 固定校验顺序为：声明求值 → 顶层结构/未知字段 → 字段类型与三态 → 名称、路径、来源规范化 → 文件存在/包含、重复和跨字段冲突 → 工作区/依赖/插件/入口校验 → 生成内部规范化结果 → 依赖解析与插件执行。
- `dir`、已解析 Git 修订、派生路径等只存在于内部规范化结果，不回填用户声明参与语义判断。

### 第二轮：名称、路径和声明结构的可比较性

用户答复：`全部按推荐`，确认 Q6–Q10。

- 逻辑名称与物理路径分开校验。包名、依赖引用名、插件 ID 使用 ASCII `[A-Za-z0-9][A-Za-z0-9._-]*`；模块导出名、程序名、导入名、alias、options key 使用 ASCII Jai 风格标识符 `[A-Za-z_][A-Za-z0-9_]*`。名称比较统一 ASCII 大小写不敏感，诊断保留原始拼写；Unicode 不作为标识符输入。
- Unicode 可出现在描述、选项值和路径中。路径字段统一分隔符、消解 `.`，拒绝绝对路径和规范化后越界的 `..`；路径规范化值进入内部结果，用户原始值用于诊断。
- 包内入口、成员目录、default_members 和插件模块路径都必须通过物理包含检查；入口必须是普通文件，目录、符号链接和 junction 不能绕过包根。后续仍需明确普通依赖来源及外部工具路径的例外边界。
- 内部模型保留对象 presence 与 AUTO/EXPLICIT_EMPTY/EXPLICIT_VALUES 三态。公开包装随后由 Q25 撤回：用户使用普通 Package 字段、嵌套 workspace 和数组；显式空数组不同于省略，显式 workspace = .{} 不应被当作没有工作区。
- 未知顶层/嵌套字段和明确不支持的旧字段严格报错。包 name/version 必填；workspace 可没有包身份/version。version 是包元数据，不参与 Git 修订或版本范围求解。
- Jai 声明求值不作为安全沙箱；只有最终 Manifest 数据属于受支持契约，副作用不作为字段来源或稳定语义。

### 第三轮：来源联合类型、字段互斥与默认推断

用户答复：`全部按推荐`，确认 Q11–Q15。

- 普通依赖和插件启用使用互斥的 `Source` 联合值，恰好选择 PATH、GIT、WORKSPACE 一种。PATH 相对声明包根；GIT 携带 URL 及至多一个 branch/tag/rev；WORKSPACE 不携带替代 path，也不因同名成员回退。模块选择的 `path` 仍相对来源根。来源缺失、多来源或字段与 kind 不匹配均失败。
- 默认优先级固定为显式合法值优先；字段省略才触发自动发现/默认值；显式空集合关闭类别；显式值非法、入口缺失或必填字段缺失均直接失败，不回退。
- 包与工作区通过同一个 `PACKAGE :: Package.{...}` 的字段表达：`workspace` 保留为 Package 内部声明字段。包身份字段与 workspace 可共存；只有 workspace 而没有包身份/能力字段时表示纯工作区。加载器内部仍保留 presence 区分，但用户不写 Manifest、Some 或独立 WORKSPACE。
- package.name 必填且不从目录名/cwd 推导。自动发现的模块/程序未显式命名时取包名；显式单项可省 name，多项必须逐项命名。非法、同类重复或隐式转换均失败。
- Git 来源最多选择 branch/tag/rev 之一；全部省略使用仓库默认分支。rev 是来源选择，不是 package.version。插件不重复声明独立 version，入口兼容性单独检查；包 version 不自动约束依赖或插件。

### 第四轮：名称冲突、路径身份与字段矩阵

用户答复：`全部按推荐`，确认 Q16–Q21。

- 名称比较按作用域统一 ASCII 大小写不敏感：同包内模块/程序/依赖引用/插件 ID/options key 判重；模块与程序跨类别可同名；不同工作区成员目录可同名包，按包名选择时报告歧义。alias 不得与本包模块、其他依赖导入名或编译器标准模块冲突。`.`、`..`、空名称和内置插件保留名不作为外部插件 ID。
- 路径分逻辑和物理两层：逻辑层统一 `/`、消解 `.`，拒绝越界 `..`，保留原始 Unicode/拼写用于诊断；物理层按当前文件系统确认存在性、包含关系和文件类型。Windows 大小写别名按同一物理路径处理，大小写敏感系统按实际文件系统处理；同类最终指向同一物理路径失败，不按顺序覆盖。
- 包入口、成员、排除目录、default_members、插件模块路径和本地 path 依赖来源根不得经过符号链接或 junction。Git 检出继续遵守来源边界；插件外部工具绝对路径由其 options 契约处理。
- 声明状态分为 Raw Manifest、Normalized Manifest、Resolution State：前者只保存用户输入和三态，后者保存规范化逻辑/物理路径和校验结果，解析状态保存 Git 修订、缓存选择和上下文。`dir`、绝对路径、已解析修订和派生目录不回填公开声明；解析失败不污染旧状态。
- 每个 package.jai 必须提供唯一 `PACKAGE :: Package.{...}` 入口，workspace 为其内部字段。可有供其使用的常量和纯编译期辅助表达式，但加载器只读取 PACKAGE；缺失、重复或类型不匹配失败，其他顶层变量不隐式并入声明。
- 字段矩阵固定：package.name/version 必填；modules/executables/dependencies/plugins/workspace.members 等列表区分省略、显式空和非空；plugins 省略为 load+test-block，显式空不启用插件；default_members 按工作区位置默认，显式空无默认；default_run 省略按程序数处理，显式值必须匹配程序。显式错误不回退。

### Q25 修订：保持原有 Package 声明形态

用户明确要求：配置应尽量简单，不能在 `package.jai` 中增加 `Manifest`、`Some`、`Configured_List` 等内部建模包装；示例应沿用原来的 `PACKAGE :: Package.{ ... }` 风格。随后用户确认 workspace 继续在 Package 内部定义，不新增顶层 WORKSPACE。

公开入口保持唯一的 `PACKAGE :: Package.{...}`：

```jai
// 只有包
PACKAGE :: Package.{
    name = "app",
    version = "1.0.0",
}
```

```jai
// 包与工作区共存
PACKAGE :: Package.{
    name = "app",
    version = "1.0.0",
    workspace = .{
        members = string.["apps/editor", "libs/core"],
    },
}
```

```jai
// 纯工作区
PACKAGE :: Package.{
    workspace = .{
        members = string.["apps/editor", "libs/core"],
    },
}
```

语义：

- `PACKAGE` 是唯一公开入口，workspace 仍是 Package 内部字段。
- 当 name、version、产物、依赖等包身份/能力字段均未声明，而 workspace 存在时，表示纯工作区，不生成假的根包。
- 一旦声明包身份或包能力，name 与 version 必须同时存在并合法。
- 两者都没有是声明错误。
- Manifest、对象 presence、三态模式和规范化状态只存在于加载器内部，不出现在用户配置中；加载器必须区分字段省略与显式空列表，不能以普通 Jai 数组零值猜测。

该确认替代先前 Q1/Q13/Q20 中公开 Manifest、Some 和独立 WORKSPACE 的建议；仅保留内部状态分层，不改变纯工作区、包与工作区共存、显式空列表关闭自动发现等既定语义。

### 第五轮补充：错误处理、空字符串、迁移与提交边界

用户答复：`Q22–Q24、Q26 按照推荐`。

- Q22：按求值、结构、字段/三态、名称/路径/来源规范化、语义、入口/文件系统检查分阶段诊断。一个阶段可收集彼此独立的错误，但失败时不发布可供执行的规范化结果；同阶段保持稳定顺序，成员按规范化相对路径排序。不以部分有效结果继续命令执行。
- Q23：必填字符串缺失或空值均失败；可选字符串省略才触发默认语义，显式空值不作为省略。description 允许空值；插件 option value 由该插件 schema 决定是否允许空值。显式空 path/name/version/branch/tag/rev/default_run 非法。
- Q24：旧 type、targets/main_file、旧插件成员名猜测和 build_script 等给出迁移错误，不静默兼容或部分接受新旧字段。`Package.workspace` 按用户修订继续保留，不属于退役字段。诊断说明问题字段和可用替代，源码定位受实际可取得的位置约束，不伪造行号。
- Q26：每个消费上下文只在完整声明、依赖和插件校验成功后发布新的规范化结果/解析状态；失败保留旧解析状态但本次操作失败。已下载内容、部分插件输出或部分成员成功均不代表整体成功；不回写 package.jai 的 dir、物理绝对路径、解析修订或派生路径。既定的逐上下文提交、后续编译失败不回滚已成功解析状态继续适用。

### 收口核对：简单字段的省略状态

[普通 Package 字段的省略状态实验](../docs/design/package-declaration-presence-check.md) 已用 Jai beta 0.2.009 完成两次成功编译和运行断言。数组、字符串和嵌套对象可使用字段特定默认值区分省略与普通显式值，公开配置不需要包装；但显式构造相同默认标记会与省略碰撞。实验不是产品实现，也未验证初始化元数据。

### 第六轮补充：内部省略标记

用户答复：`确认`，确认 Q27。

采用字段特定的内部省略标记，保留普通 `PACKAGE :: Package.{...}`、嵌套 workspace 和数组写法。标记必须与合法名称、路径及条目不相交，不成为可手工填写、伪造或复制以控制行为的配置值。显式空数组仍表示明确零项，显式空 name/default_run 等按 Q23 报错。

记录的是求值后的配置状态，不保证恢复字段在源代码中是否写过。用户接受手工构造保留内部标记不属于受支持输入；因此本轮不增加初始化元数据追踪，也不向用户增加包装或开关。实验只证明表达机制，不代表新的 Juice 加载器已经实现。

## Resolution

Q1–Q27 已经用户逐轮确认；Q25 的简洁配置修订覆盖早期公开 Manifest/Some/独立 WORKSPACE 提案。本票完成声明表达和校验契约的设计，未修改生产接口、求值器、插件或解析状态实现。

### 1. 唯一公开入口与纯工作区

`package.jai` 继续提供唯一 `PACKAGE :: Package.{...}`，workspace 为普通嵌套字段。允许辅助常量及纯编译期表达式，但只读取 PACKAGE，不按其他顶层名字隐式合并配置。缺少 PACKAGE、重复定义或类型不匹配均失败。

- 声明任意包身份/能力字段时，必须同时提供合法 name、version。包身份不从目录名或 cwd 推导。
- 仅声明 workspace、所有包身份/能力字段均省略时，为纯工作区，不生成空根包，也不进行根包产物自动发现或默认插件启用。
- 包与 workspace 同时声明时共存；workspace 省略表示没有本地工作区声明，不能把类型的零值当作已声明工作区。
- 显式 `workspace = .{}` 表示存在的空工作区；既无包字段又无 workspace 是错误。
- 显式空 modules/dependencies/plugins 等仍是包能力配置，不能靠空清单伪装成纯工作区；需要这样的根包须写 name/version。
- 公开配置不出现 Manifest、Some、Configured_List、presence/mode 开关或单独 WORKSPACE 入口。旧 `Package.workspace` 的移除建议已撤回。

### 2. 省略状态与字段矩阵

普通字符串、数组和嵌套结构保留字段特定的内部默认标记；读取最终数据时识别省略，然后转换为内部的未配置/显式空/显式非空状态。不根据普通数组 `count == 0` 推断省略，不以空字符串代表未配置。合法配置值与内部标记必须不相交；标记是实现保留值，不能作为受支持配置手工构造或复制。此机制承认数据状态，不声称恢复任意源代码初始化历史。

| 字段 | 省略 | 显式空 | 显式非空 |
|---|---|---|---|
| name、version | 包存在时必填；纯工作区不要求 | 错误 | 合法名称、非空版本元数据 |
| description | 默认空描述 | 允许空字符串 | 原样保存 |
| modules | 固定入口自动发现 | 零模块，关闭自动发现 | 只采用列出项 |
| executables | 固定入口自动发现 | 零程序，关闭自动发现 | 只采用列出项 |
| dependencies | 无依赖 | 无依赖 | 校验每条显式引用 |
| plugins | 内置 load、test-block | 不启用任何插件 | 仅启用列出项 |
| workspace | 没有本地工作区声明 | `.{} ` 为已声明空工作区 | 应用成员/默认选择规则 |
| workspace.members | 零显式成员 | 零显式成员 | 展开候选；根包资格仍按工作区规则 |
| workspace.exclude | 无排除 | 无排除 | 排除命中目录及候选子树 |
| workspace.default_members | 工作区既定默认选包 | 无默认选择 | 仅指定成员 |
| default_run | 唯一程序可运行；多程序要求选择 | 空字符串错误 | 必须匹配本包程序 |
| Dependency.modules | 来源根唯一公开模块简写 | 普通依赖能力不匹配 | 只选择列出模块 |
| 模块选择 path | 来源根，即 `.` | 空字符串错误 | 来源根内明确包目录 |
| 模块选择 name | 目标包唯一公开模块 | 空字符串错误 | 匹配目标包公开导出 |
| 模块选择 alias | 沿用导出名 | 空字符串错误 | 消费包内导入名 |
| plugins[].options | 插件默认配置 | 不覆盖默认配置 | 按插件 schema 校验 |

显式合法值优先；显式错误不回退。提供方显式模块/程序列表中，唯一一项可省略 name 并取包名，多项必须逐项命名；entry 必填。自动名称还须满足对应类别语法：例如包名 `my-app` 合法，但不能据此生成含连字符的模块名/程序名，须显式命名。

必填字符串缺失与显式空均报错；可选字符串仅在省略时触发默认。description 可空，插件 option value 是否可空由插件 schema 决定；显式空 path/name/version/alias/branch/tag/rev/default_run 等不等同于省略。版本只作元数据，不求解范围，也不与 Git tag 自动匹配。

### 3. 名称与冲突作用域

| 名称种类 | 语法 |
|---|---|
| 包名、依赖引用名、插件 ID | ASCII `[A-Za-z0-9][A-Za-z0-9._-]*` |
| 模块导出名、程序名、导入名/alias、options key | ASCII `[A-Za-z_][A-Za-z0-9_]*` |

名称比较使用 ASCII 大小写不敏感的比较键，诊断保留原始拼写。不修剪空白、替换连字符、Unicode 转写或自动更名；描述、选项值及路径可使用 Unicode。Git 地址、Git selector、文件路径和 option value 不是逻辑名称，不能套用上述小写比较键。

- 同包同类模块名和程序名分别判重，跨类别同名允许。
- 依赖引用名在消费包内判重；导入名还须与本包模块、其他依赖导入名和编译器标准模块检查冲突。
- 插件 ID 在消费包启用范围内判重；options key 在所属插件配置内判重，不把不同插件的同名选项当作重复。外部插件 ID 不得使用空值、`.`、`..` 或内置保留名。
- 工作区不同目录可有同名包；按包名选择时歧义失败，不在成员发现时拒绝所有同名包。
- 相同实际依赖模块的重复选择失败，即使引用名/alias 不同；插件身份还须遵守插件票的同一实际插件规则。
- 成员的重叠目录匹配按工作区票去重。成员去重、入口重复报错、模块重复引用报错属于不同契约，不能统一为一种处理。

### 4. 路径基准、物理身份与来源联合

先保留原始文本供诊断；逻辑规范化统一目录分隔符为 `/`、消解 `.` 和 `..`，在字段规定的根边界内检查包含关系。再以文件系统核对实际路径身份、存在性及类型。入口必须是现存普通 `.jai` 文件，不是目录。受约束路径链中的符号链接和 junction 拒绝，不用它们跨越包/工作区/来源根。

| 字段或操作 | 基准与边界 |
|---|---|
| modules/executables 的 entry | 提供方包根内相对文件路径 |
| members/exclude/default_members | 工作区根内相对目录/受支持模式 |
| Dependency.modules[].path、插件模块 path | 对应来源根内相对包目录 |
| 普通本地 Source.PATH | 相对声明包根定位，保留既定的兄弟包引用能力；目标确定后作为来源根 |
| Git 包内部 PATH | 仍相对声明包，但必须留在该检出内并保留 Git 身份 |
| 插件派生输出 | 当前消费工程私有派生目录，不能回写来源根 |
| 插件外部工具路径 | 由插件 options 契约处理，不套用源码入口的相对路径规则 |

包内、工作区内和模块选择相对路径拒绝绝对及规范化后越界输入；这不撤回本地 source.path 引用兄弟包的既定能力。拒绝符号链接/junction 的规则也适用于本地来源根。exclude 无匹配可合法，不能为一个未匹配排除项凭空要求目录存在；实际匹配候选才进入物理检查。

路径身份尊重文件系统：Windows 大小写别名视为同一路径，大小写敏感系统按实际路径区分，不将整条 Unicode 路径套用 ASCII 名称比较。不承诺不同文件系统的文件集合完全相同。同类产物的规范化入口重复失败；path/workspace 在各自资格校验通过后，可按同一本地包目录识别为同一提供方。

来源采用带类型标记的互斥 Source 值，缺类型和不匹配载荷均失败：PATH 只携带路径载荷，GIT 只携带 Git 载荷，WORKSPACE 不携带替代 PATH。Git 载荷要求非空地址；branch/tag/rev 至多一个，显式空 selector 失败，全省略采用默认分支。引用名与导入别名不参与来源身份。

Git 地址及 selector 的具体语法校验采用 Git 对地址、引用和修订的规则，不把包名语法或版本范围语法套入其中；selector 必须解析为确定提交，错误/歧义不回退到同名成员。完整修订由仓库对象格式确定，短修订不能冒称完整提交，离线缺状态时仍只接受具备全部内容的完整提交。地址规范化不能因包名相同或检出内容相同而合并来源；身份仍包含来源、已解析提交、仓库内包目录及导出。

### 5. 求值、内部状态与错误阶段

允许 Package 字面量、常量、数组/结构体构造和纯编译期辅助表达式；只承认最终声明数据。网络、进程、环境探测、文件写入不是受支持的声明能力，插件和构建脚本不得在声明求值阶段被框架调度。首版不承诺静态拦截任意 Jai 代码的副作用；子进程不等于安全沙箱。

内部明确分离：

- 原始声明：用户值、内部省略状态和可取得的定位信息；不回填运行时路径。
- 规范化结果：校验通过的包/工作区归属、名称、逻辑路径、实际包根与来源描述；未全部通过前只在临时结果内构建。
- 解析状态：按消费上下文及声明包/来源记录 Git 选择，不能只用共享源码路径作为上下文键。派生文件属于当前操作，不是用户清单或 Git 修订选择。

最终诊断阶段按后确认的 Q22 排序：求值 → 顶层结构 → 字段/省略状态 → 名称/路径/来源规范化 → 包/工作区/依赖/插件语义 → 入口和文件系统检查。步骤间存在依赖时只校验已经具备前提的对象，不为凑错误数量对无效路径继续执行后续操作。远程提供方内容尚未取得时，只有本地可判定的声明检查可先完成；取得内容后仍须在发布解析状态、执行插件 hook 前完成对应提供方检查。

一个阶段可收集独立错误，阶段失败不发布部分可执行结果。错误至少标明声明文件、字段路径/列表项及原因；有可靠源码位置时给出位置，没有时不伪造行号。具备源位置的同阶段错误按源顺序；求值数据未保留源位置时按确定的字段/列表顺序报告，成员按规范化相对目录排序。规范化字段不能被当成用户原始输入再次参与默认判断。

未知字段及不支持的旧字段均失败。Jai 可在编译声明时拒绝类型/未知成员，不能声称所有错误都能延迟到自定义加载器；应保留编译器诊断，并在可准确定位时补迁移提示。不按名字读取并忽略未知协议记录，也不接受部分新字段来掩盖旧字段。

### 6. 提交边界、缓存与不回退

每个消费上下文在完整声明、依赖图和适用的插件校验全部成功后，才能发布新的规范化结果及完整解析状态；部分结果不进入执行。获取、模块选择、身份/名称冲突、环检查等失败时保留旧状态，本次操作失败。状态损坏/不可读不是“缺失”，不能隐式重建。

原子性按已定的消费上下文成立，不是整个工作区事务：批量操作中先前成功包保持其结果，失败包保留旧状态，后续包不执行。已成功解析之后的 hook/派生输出/编译执行失败仍使命令失败，但不能把已保存解析状态当成未解析；不回滚已完成解析以伪装本轮没有运行。仅下载内容或生成部分输出不代表解析或命令成功。

XDG 源码缓存和状态分离延续 [依赖解析决定](0081-decision-dependency-identity-sources.md#resolution)：绝对环境值优先，相对值警告并回退；有效配置不可写报错，不能静默改 cwd/临时目录。缓存清理不删除选择，工程移动到新规范化根是新上下文，改变 cwd 不是。声明文件不保存 dir、已解析提交或派生目录，实际绝对路径只在内部结果使用。

### 7. 最小公开声明草案

以下使用拟议的新 Package 字段，保持普通 Jai 结构体/数组写法；省略标记由类型默认值实现，用户不填写。新的完整 `#import "Juice"` 接口尚未实施，这些示例不能当作当前安装版本的通过证据。数组/字符串/嵌套值机制的实测范围见下一节。

```jai
#import "Juice";

// 仅包：模块和程序各按已定固定入口自动发现。
PACKAGE :: Package.{
    name = "app",
    version = "1.0.0",
};
```

```jai
#import "Juice";

// 纯工作区：不创建根包，不为根目录自动发现模块/程序。
PACKAGE :: Package.{
    workspace = .{
        members = string.["apps/editor", "libs/core"],
    },
};
```

```jai
#import "Juice";

// 包与工作区共存；业务模块、程序都显式选择。
PACKAGE :: Package.{
    name = "suite",
    version = "1.0.0",
    modules = .[.{name = "Suite", entry = "src/module.jai"}],
    executables = .[.{name = "suite", entry = "src/main.jai"}],
    default_run = "suite",
    workspace = .{
        members = string.["apps/*", "libs/*"],
        default_members = string.["apps/editor"],
    },
};
```

```jai
#import "Juice";

// 零公开产物的包仍有身份；显式空不回退自动发现。
PACKAGE :: Package.{
    name = "checks",
    version = "1.0.0",
    modules = .[],
    executables = .[],
    plugins = .[],
};
```

### 8. 验收矩阵与技术证据

| 输入/场景 | 预期结果 |
|---|---|
| PACKAGE 缺失、重复或不是 Package | 求值/结构错误，不搜索替代入口 |
| `PACKAGE :: Package.{}` | 无包、无工作区，错误 |
| 只有 `workspace = .{}` | 空纯工作区，声明合法；命令选零包仍按工作区票失败 |
| workspace 加显式空 modules，但不写 name/version | 存在包能力配置，身份缺失错误 |
| 只有 name 或只有 version | 包身份不完整，错误 |
| name/version/default_run 显式空字符串 | 字段错误，不用省略默认 |
| modules 省略，两个自动模块入口同时存在 | 歧义错误 |
| modules 显式单项，两个自动入口同时存在 | 仅校验被选项，不校验未采用的自动候选冲突 |
| modules/executables 显式空，但默认入口存在 | 对应类别仍为零项 |
| `my-app` 作为包名，自动模块沿用包名 | 模块名不满足标识符规则，要求显式合法名称 |
| 模块 Codec 与 codec 同类并存 | 大小写等价冲突 |
| 同包模块和程序同名 | 跨类别允许 |
| 两个工作区成员包同名 | 声明允许，按包名选择时歧义 |
| 两条 members 规则命中同一目录 | 按工作区决定去重 |
| 同类产物入口 `src/a.jai` 与 `src/./a.jai` | 同一规范化入口，失败 |
| 普通本地 source.path 指兄弟包 | 允许；仍校验该来源及所选包 |
| modules[].path 越出来源根 | 越界失败，不按 cwd 重新定位 |
| 入口或本地来源路径链含 symlink/junction | 路径错误，不沿链接绕过规则 |
| path/workspace 最终选择同一本地模块 | 先验证各自资格，再报重复模块 |
| 来源缺 kind、同时携带冲突载荷 | 结构错误 |
| Git 同时写 branch 与 rev，或显式空 rev | selector 错误，不用默认分支 |
| 插件清单省略 / 显式空 | 默认 load+test-block / 不启用插件 |
| 未知 option key 或重复 key | 插件配置错误，hook 前失败 |
| 使用旧 type、targets/main_file、build_script | 迁移错误；不静默兼容 |
| 使用嵌套 workspace | 继续支持，不属于旧字段错误 |
| 显式复制/伪造内部省略标记 | 不属于受支持配置；不承诺恢复其源码初始化历史 |
| 某阶段失败但已有部分可用对象 | 不发布可执行的部分规范化结果 |
| 依赖解析失败但已下载部分内容 | 保留旧解析选择，命令失败；缓存内容可保留 |
| 已成功解析后编译失败 | 命令失败，保留已成功提交的解析选择 |
| 未选成员的声明错误 / 无关远程依赖不可取得 | 前者阻止工作区操作；后者不单独触发获取/失败 |

[普通 Package 字段的省略状态实验](../docs/design/package-declaration-presence-check.md) 使用 Jai beta 0.2.009，完成两次编译及数组、字符串、嵌套对象、标记碰撞断言。它证明内部特殊默认值可承载已确认的普通写法，也证明显式构造保留标记会与省略等价；Q27 已接受后一个限制。未实现完整 schema、序列化协议、源位置采集或新的 Juice 公共模块，不把实验扩大成完整实现通过的结论。
