## Question

以 [声明表达与校验契约](0084-decision-declaration-evaluation-validation.md#resolution) 及其前置决定为输入；与 [测试能力迁出地图](0065-map-test-migration-to-testing-package.md) 的交互仅记录影响，不代替对方决策。

怎样把新声明语义交接为可实施规格，使现有包能明确迁移，并验证包/产物、依赖、工作区和插件的规则能组合使用？

需给出现有字段逐项保留、改名、拆分或移除的迁移表；旧声明的拒绝/诊断策略及是否需要短期过渡；覆盖最小程序、只提供模块、模块加程序、纯工作区、路径/Git/成员依赖和 lint/jaix 插件的成套示例。检查 bootstrap、发布的 Juice 模块面、安装后清单求值及现有测试迁移地图的交接约束，不能默改另一 effort 的决定。

提供方迁移至少覆盖 [声明模型决定](0080-decision-package-products-defaults.md#resolution) 的 type 移除、targets/main_file 到 executables/entry、模块显式导出、两处自动模块入口从优先选择改为歧义错误、单项默认名/多项必填名、显式空清单不回退及同类重名/重复路径。将票内语义矩阵转为最终可表达的 Jai 示例时，必须使用声明校验票已经确认的类型写法，不把语义伪代码当成编译通过的配置。

依赖迁移以 [依赖解析决定及失败表](0081-decision-dependency-identity-sources.md#resolution) 为完整输入；需要覆盖普通依赖清单要求：旧无 package.jai 模块如何补声明或通过包装包引用；path 从命令 cwd 改为声明包根定位；字符串猜来源和同名成员覆盖退役后的诊断。包装不得绕过包内源码入口规则；编译器内置模块不自动归入普通包依赖。第九轮还要求覆盖：旧 package 名称搜索字段退役，依赖引用名与模块导入名分离，提供方自行声明所需依赖而不再由最外层包重述传递依赖，同一消费包的同模块多别名被拒绝，以及 modules = [] 不能充当普通导入依赖。用最小正反例验证包内支持模块不会泄漏给消费者；无锁文件的本机 Git 解析状态不得被描述为跨机器可复现保证；不同工程的选择记录相互隔离但可共享全局 Git 内容缓存。依赖不支持版本范围求解，旧 version 字段不得静默丢弃；导入名冲突须由用户显式 alias 解决，不能由工具自动重命名。迁移验收还需覆盖 package.jai 依赖环的明确诊断，以及不同工作区成员分别解析同一浮动 Git 来源时更新选择互不覆盖。

缓存迁移还需覆盖依赖讨论第十三轮的分层：清理 XDG 源码缓存不删除工程选择，明确删除状态或将工程移至新规范化根可引起重新解析；不同平台采用已确认的 XDG/默认目录，不照搬 Cargo Home 或保留原实现的临时目录兜底。共享 Git 源码不得被插件或生成流程回写。这些均为验收要求，不在本票执行缓存删除或状态搬迁。补齐显式更新覆盖当前上下文全图、更新失败保留旧选择但不报告成功、解析后编译失败不回滚选择、状态损坏不自动重建，以及离线完整哈希/浮动修订的正反例。引用名/别名/模块列表调整不得隐式追新；具体 update/选包/offline 命令契约已由 [工作区选包决定](0082-decision-workspace-members-selection.md#resolution) 明确，交接示例须采用该入口。

跨来源组合验收须包括：外部 Git 包使用同一检出内的提供方 workspace 而非消费方同名成员；path/workspace 指向同一本地包的同一导出时报重复、不同导出可并存；未满足 workspace 成员资格时不得降级成可用的 path 引用；Git 内部 path 可指向同检出非成员包并保留提交身份，越出检出必须失败，本地开发包的兄弟路径仍可用。

工作区迁移采用 [工作区选包决定的目录树和验收表](0082-decision-workspace-members-selection.md#resolution)。须覆盖原先只以 cwd 定位改为向上寻找最近声明、纯工作区与根包共存表达、成员通配/exclude 实际生效、成员或根调用的不同默认选择、显式空 default_members、重名成员路径消歧、嵌套工作区隔离及子包测试扫描边界。CLI 示例须包括 --workspace、-p/--package、--package-path、update 和 --offline；验证 run 不再按包同名程序回退且只构建所选程序，多包 run 失败，零包错误与零测试成功分开。还需覆盖未选成员声明错误阻止操作、无关远程依赖不被获取、批量失败停止并保留已成功包/上下文结果。上述是新行为的迁移与验收要求，不声称当前实现已支持，也不代替另一测试迁移 effort 的决定。

本票的公开配置写法以 [Jai 声明表达、默认值与校验契约](0084-decision-declaration-evaluation-validation.md#resolution) 为准：保留唯一 `PACKAGE :: Package.{...}`，`workspace` 继续嵌套在 Package 内部；纯工作区只填写 workspace，不生成假根包。不向清单作者暴露 Manifest、Some、三态包装或第二个 WORKSPACE 入口；`Package.workspace` 不列入旧字段移除表。示例应使用普通结构体和数组，不把内部 presence/规范化状态泄漏到配置。Q22–Q24、Q26 已确认分阶段失败、空字符串不等于省略、其他旧字段严格拒绝以及按消费上下文原子提交；禁止把包级成功扩张为整个工作区已成功。完整对拍须覆盖简单写法下的字段省略/显式空/非空，而不只验证非空示例。

Q27 已接受内部保留标记，不要求对手工构造这些标记恢复源码初始化历史；[省略状态实验](../docs/design/package-declaration-presence-check.md) 只验证独立 Jai 类型默认值机制，不能当作当前 Juice 完整新接口已经可用的证据。交接需采用声明票字段矩阵和验收表：包括含连字符包名默认导出失败后的显式命名、工作区路径去重与模块引用重复失败的不同规则、非空/空/省略 default_run 以及纯工作区不自动生成根包能力。来源 URI/Git 校验、解析状态及插件兼容性的组合样例仍须核对前置决定，若发现必须改变观测语义，应作为新决策提出，不在迁移示例中暗增限制。

完成条件：验收场景与新旧行为差异明确，声明示例无矛盾，剩余开放问题可判断是新决策票还是出范围；指明规格整理的落点与完成标准。本票只决定迁移与交接契约，不执行批量迁移，不将它伪装成实现任务。

### 2. 字段迁移矩阵

| 旧字段或行为 | 新声明/行为 | 迁移动作及失败边界 |
|---|---|---|
| `PACKAGE :: Package.{...}` | 继续作为唯一入口 | 保留；不加入包装或第二个入口 |
| Package.name/version | 包身份与版本元数据 | 有根包时必填；纯工作区不伪造身份；版本不作依赖范围求解 |
| Package.description | 描述元数据 | 保留；可为空 |
| `type = .LIB/.BIN` | modules 与 executables 独立 | 删除 type，根据真实导出/程序填写两类能力，不能从旧角色推定另一类永远关闭 |
| `targets` | `executables` | 列表按声明语义迁移；需要旧显式清单行为时保留明确条目 |
| `targets[].main_file` / 旧 main_file | `executables[].entry` | 填包内现存 `.jai` 文件，不能用自动入口掩盖无效显式路径 |
| 模块入口按优先级选择 | modules 省略时仅固定两处候选 | 两候选同时存在必须显式选一个，否则歧义失败 |
| 包名兼任模块名/程序名 | 包名、导出名、程序名职责分开 | 单项/自动默认仍取包名，但必须满足名称语法；连字符包名应显式指定合法导出/程序名 |
| 空列表与未配置混用 | 省略、显式空、非空有不同语义 | 逐字段保留作者意图；用户不填写内部标记/mode |
| `workspace` 嵌套字段 | 继续保留 | 根包与纯工作区共用同一写法；不得列入废弃字段 |
| `workspace.members` 精确路径列表 | 精确目录或受支持的单层 `*` | 明确成员范围；缺失/无匹配错误，重叠结果去重 |
| exclude 未实际影响成员发现 | exclude 排除候选目录及子树 | 迁移后重新核对成员集合，不能把旧忽略行为当作兼容保证 |
| 工作区根即默认操作根包 | default_members 与调用位置分离 | 按工作区决定确认根、成员及子目录默认选择 |
| 无根包的组织目录需假包 | 只有 workspace 的 Package 声明 | 移除假的身份/能力字段；显式空包能力仍表示包配置 |
| `Dependency.source` 字符串猜来源 | 明确 PATH/GIT/WORKSPACE 来源 | 作者选择真实来源，工具不猜同名成员或自动转换 |
| 依赖 version / package 搜索或断言字段 | 来源 selector 与明确模块选择 | 不静默丢弃；把真实 Git 修订意图写入 branch/tag/rev，把包位置写入 modules[].path |
| 依赖引用名即导入名 | Dependency.name 与模块 name/alias 分开 | 引用名只标识配置项；代码使用导出名或显式 alias |
| 消费方重述上游传递依赖 | 提供方各自声明依赖 | 修正提供方声明；消费方只声明直接使用的模块 |
| 同一模块多条 alias 引用 | 同一实际模块最多选择一次 | 合并业务引用或修改代码；不能用 alias 绕过重复判定 |
| 来源目录没有 package.jai | 每个普通提供方包有合法声明 | 上游补声明或使用符合包内入口规则的包装包，不能直接选任意源码文件绕过声明 |
| 本地路径随命令 cwd 解释 | 相对声明包根 | 将路径改为稳定的包相对引用；合法兄弟包引用继续支持 |
| 同名成员覆盖显式来源 | 来源不可隐式替换 | workspace 引用显式声明；Git 来源仍取指定检出 |
| 旧插件 id 按成员名查找、version 精确检查 | 插件来源、模块选择和兼容检查分开 | 明确来源和插件公开模块，不另填插件 version，不自动进入业务导入范围 |
| 缺少转换能力时自动补默认插件 | 省略 plugins 才用 load/test-block | 非空清单须显式列出所需内置项；空清单禁用全部 |
| 普通依赖与插件重复选择同一模块 | 插件采用独立来源方案 | 同模块重复失败；业务 API 由另一公开模块提供 |
| `build_script` 被接受但不执行 | 清单不再调度该字段 | 报迁移错误；自动扩展用插件，独立脚本由用户另行调用 |
| 包内/共享检出生成或改写源码 | 当前消费包私有派生视图 | 改为注册 substitute/drop/generated，保留逻辑路径，禁止回写源树 |
| Package.dir 等加载器回填字段 | 内部规范化/解析状态 | 从用户声明面移除，不把运行路径重新当作声明输入 |
| 旧全局/临时目录内容充当解析选择 | XDG 内容缓存与工程解析状态分开 | 不以缓存 HEAD 或其他工程记录猜本工程选择；既有状态按已定规则复用或明确报错 |
| run 按包同名目标回退、先 build 全部 | 显式/default_run/唯一程序选择 | 多程序缺选择失败；只编译所选程序及所需依赖 |

原始声明仍是 Jai，不承诺能在编译器报未知字段之前拦截所有错误。迁移诊断至少保留编译器错误并说明字段替代；有可靠位置才给源码行号。混写新旧字段不能使旧字段被部分接受。

### 3. 迁移切换与发布单位

- 同一工作区根包和全部成员声明协同迁移。整体声明校验继续有效，即使本次只选一个成员也不能把其他成员的无效声明当作可忽略。
- 所选包真正使用的依赖、传递依赖和插件必须提供兼容声明。不兼容时报告引用链及提供方位置，作者明确选择兼容 Git 修订或补齐声明；工具不自动切分支、追新、换来源或回退旧语义。
- 未选成员的无关远程依赖不因为整工作区声明检查就被获取；被选依赖图确实需要的包仍按其上下文解析。不得把“整工作区清单迁移”扩大为一次网络操作更新所有包。
- 可执行文件与相邻 `modules/` 构成完整交付单位，内部检查公开声明类型、求值协议和插件入口兼容性。缺失/错配明确失败，不使用其他安装目录兜底。
- 发布物自行携带兼容信息，用户清单不增加版本开关。兼容信息不是包元数据 version、Git selector 或用户插件 version 的复活。
- 升级/回退使用完整配套版本。新声明不承诺能被旧运行时理解；回退软件不能被描述为会自动逆向改写新清单或搬迁解析状态。
- 不新增自动改写命令，不执行本轮范围外的缓存删除、状态搬迁或发布。

### 4. 必备示例集合

下列编号是交接追踪键，不是新决策票。每例最终必须具备目录树、完整 package.jai、命令/cwd、预期产物或错误以及对应规则链接。不得只给省略依赖项的片段作为完成证据。

| 示例 | 必需内容和正例 | 必需失败反例 |
|---|---|---|
| E01 最小程序 | 一个有效包、src/main.jai；根/源码子目录的 build/run | name/version 缺失、显式无效入口不回退 |
| E02 仅模块 | 合法导出、零程序；build 的零程序结果和独立消费方导入 | run 无程序；两处自动模块入口歧义 |
| E03 模块加多程序 | 同包模块和程序共存、default_run 与显式程序选择 | 多程序无选择、无效 default_run、同类重名 |
| E04 纯工作区 | Package 内只声明 workspace，多成员/default_members | 空选择、默认成员非成员、根位置不存在包却选择 `.` |
| E05 根包工作区 | 根包和 members/exclude 共存，根/成员/子目录选包 | 未选成员声明错误、同名包选名歧义、嵌套成员越界 |
| E06 本地与工作区依赖 | 兄弟 path、显式 workspace、导出选择与 alias | 来源根越界、非成员 workspace、不合并来源资格、同模块重复 |
| E07 Git 与解析上下文 | 本地 Git 仓库、分支/tag/rev、提供方内部 workspace/path | 离线缺选择/内容、错误 selector、越检出根、更新失败保留旧选择 |
| E08 lint 插件 | 显式来源/公开插件模块；按需列出 load/test-block | 无插件入口、同插件重复、未知 option、不隐式补默认项 |
| E09 jaix 与辅助 API | 插件模块与普通 API 模块分开选择；config/exe 及派生输出 | 重复选择插件模块、输出冲突/遗漏注册、工具失败、源树改写 |
| E10 零公开产物与空配置 | `.[]` 关闭自动发现，测试专用包，options 默认与空值区别 | 空字符串不是省略，包能力字段出现却缺身份 |

E08/E09 使用本仓现有 lint/jaix 作为迁移案例，但必须核实新公开导出名。当前 `juice-plugin-lint`、`juice-plugin-jaix` 含连字符，不能直接变成符合新模块标识符规则的默认导出；应显式取合法名，不能自动删连字符。Juice 的 jaix PRESTEP 插件与另一 effort 的 Jaix test-block AST 插件必须分别说明，不以名字相近当作同一模块。

以下片段仅固定本票迁移说明的公开写法，不是完整 E01–E10 或当前 Juice 编译成功的证据。示例名 app 满足程序名规则，所引用入口须真实存在。

```jai
// 旧字段片段，迁移前。
PACKAGE :: Package.{
    name = "app",
    version = "1.0.0",
    type = .BIN,
    targets = Target.[.{name = "app", main_file = "src/main.jai"}],
};
```

```jai
// 新字段草案，模块显式关闭，保留旧的单程序意图。
PACKAGE :: Package.{
    name = "app",
    version = "1.0.0",
    modules = .[],
    executables = .[.{name = "app", entry = "src/main.jai"}],
};
```

```jai
// 新的纯工作区草案，不需要 Manifest/Some/WORKSPACE。
PACKAGE :: Package.{
    workspace = .{
        members = string.["apps/editor", "libs/core"],
        default_members = string.["apps/editor"],
    },
};
```

不能机械地给所有旧 BIN 加 modules=.[]：只有作者确实要关闭模块公开能力时才如此。真正的迁移指南须说明这个意图分支，不把例子的选择扩大为通用转换规则。

### 5. 规则与组合验收矩阵

规格整理为所有关键规则分配示例或测试编号，下面是必需的组合，不替代前置票完整失败矩阵。夹具优先使用临时本地 Git 仓库，避免公网状态改变预期。

| 验收编号 | 组合/条件 | 必须观察到的结果 |
|---|---|---|
| A01 | 新旧字段及省略状态 | 旧字段严格拒绝；省略/显式空/非空按各字段契约区分；Package.workspace 保留 |
| A02 | 工作区成员与显式 Git 来源同名 | Git 引用不被成员覆盖；包名选择歧义不影响显式来源身份 |
| A03 | path/workspace 选择同一实际模块 | 各自资格先通过，再报告重复；不同公开模块可并存 |
| A04 | 多层依赖与消费包隔离 | 传递模块不泄漏为直接导入；提供方内部模块仍可正常使用 |
| A05 | 普通依赖与插件 | 插件不隐式成为业务导入；重复选择同一插件模块失败；独立 API 模块可用 |
| A06 | 内置默认与显式插件清单 | 省略用默认；空禁用；显式列表不补入遗漏默认项 |
| A07 | 插件与多程序/批量包 | 每所选包独立启用；不因程序数重复执行；run 只编译所选程序，根配置不继承给成员 |
| A08 | 插件派生视图与旧输出 | 仅本次注册输出进入编译；保留逻辑路径；冲突失败且不回写包源/共享检出 |
| A09 | 离线首次/已有解析状态 | 完整 rev 且内容齐全的缺状态例外可用；浮动选择缺记录、内容缺失均明确失败 |
| A10 | update 与失败原子性 | 完整消费图刷新；当前失败保留旧选择；工作区先前成功上下文不回滚，后续不执行 |
| A11 | 来源缓存与状态目录 | 清内容不清选择；状态损坏报错；新规范化工程根不继承旧选择；仅改 cwd 不换上下文 |
| A12 | Git 提供方内部 workspace/path | 使用检出内归属，path 不要求成员但不越检出；不借消费工程同名成员 |
| A13 | 成员校验、执行选择与测试边界 | 所有成员声明先校验；未选无关远程图不获取；父包扫描不进入下级 package.jai 子树 |
| A14 | 根/成员默认与显式 CLI | 默认成员、显式空、-p/--package-path/--workspace、零包和多包 run 分别符合契约 |
| A15 | Windows 与大小写敏感文件系统 | 名称按既定 ASCII 规则；路径按物理身份；符号链接/junction 不绕过边界；不强求文件集合相同 |
| A16 | 配套安装与错误安装 | 合法配套可在仓库外求值/运行；缺模块、新旧协议或插件入口不兼容明确失败，无其他安装目录兜底 |

每条结果标记为“预期”“已运行通过”或“尚未验证”，通过证据包含提交、编译器版本、平台、命令/cwd、退出码及输出摘要。语义草案、独立默认值实验、发现旧测试位置和旧测试通过，是不同证据，不可互相代替。

### 6. 自举、发布与安装后验证

未来实施完成至少通过三条路径：

1. **源码自举**：从相同版本源码和声明生成 Juice，现有 debug/release 自举路径均核对；根声明与发布的类型定义同步切换，不能靠环境中的旧 Juice 模块偶然通过。
2. **发布配套**：可执行文件与 modules/ 来自配套发布物；公开声明定义、求值协议和插件入口兼容检查使用同一交付契约。内部兼容标记的具体字节和生成方法可由实现确定，不向用户增加清单开关。
3. **独立安装**：把完整发布物安装到独立目录，在仓库外使用 E01–E10 的适用场景求值、build/run/test，并验证相应 update/offline/错误路径；不能依赖源码 checkout 或其他安装的导入目录。

静态核查提供的接线点：build.jai 从 src/module.jai 发布 target/modules/Juice/module.jai，之后用该模块求值根清单；安装后的 manifest 求值使用运行中 Juice 可执行文件旁的 modules。现有 bootstrap/publication 用例可作为接入位置，但尚未运行本地图的新验收，不据此声称已经覆盖混装拒绝和新声明。
