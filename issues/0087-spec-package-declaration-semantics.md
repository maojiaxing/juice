## Problem Statement

包作者需要用同一份简单的 Jai 声明描述可复用模块、程序、依赖和工作区，并从任何包内目录可靠地构建、运行或测试。当前模型仍以互斥的 LIB/BIN 角色、旧目标清单及字符串来源解释这些概念：包名容易被当成模块名，显式来源可能被同名成员覆盖，相对引用受调用位置影响，传递依赖需要重复声明，多个程序的运行选择也存在隐式规则。

工作区成员、命令默认操作对象和依赖关系尚未明确分离。插件依赖成员名发现，省略配置与显式空配置混用，可能自动补入作者没有列出的转换插件。源码获取、具体 Git 修订选择、生成源码和安装模块之间的边界也不足以保证工程互相隔离。

这使包作者难以预测新增一个模块、移动目录、修改别名、加入工作区成员或升级工具后会发生什么。维护者需要一次有明确迁移和验收标准的语义切换，同时保留用户已经熟悉的 Package 结构体与普通数组写法。

## Solution

Juice 继续使用 Jai 包声明和唯一的 PACKAGE 入口，workspace 保留为 Package 内的普通嵌套字段。用户通过独立的模块、程序、依赖和插件清单表达需求；可以只声明一个包、只声明工作区，或同时声明两者，不需要 Manifest、Some、额外模式包装或独立工作区入口。

工具明确区分省略、显式空和显式非空配置；依赖来源显式，模块引用按消费包隔离；工作区成员与命令选包分别定义。build、run、test 和新增的 update 共享明确的选包规则，离线操作及本机 Git 解析选择保持可预测。插件只按声明启用，生成当前操作的私有派生视图，不能改写源内容或声明模型。

实施需交付新公开声明、完整命令接线、配套发布、更新后的产品规格、人工迁移指南及可复现验收。旧字段严格拒绝，不保留永久兼容解析；工具不猜测迁移意图或自动改写用户配置。已关闭的决策地图是本规格依据，本票是其后的实施交接，不是新的设计访谈。

## User Stories

1. 作为包作者，我希望继续使用普通 Package 结构体作为唯一声明入口，以便升级时不学习额外的包装模型。
2. 作为工作区维护者，我希望 workspace 继续嵌套在 Package 内，以便所有配置保持原有的集中写法。
3. 作为工作区维护者，我希望只声明 workspace 就能建立纯工作区，以便不为组织成员伪造根包身份。
4. 作为包作者，我希望包和工作区能够同时存在，以便根目录既提供能力又组织成员。
5. 作为包作者，我希望一个包同时提供多个导入模块和多个程序，以便不再在库与程序之间二选一。
6. 作为测试包作者，我希望零公开模块和零程序的包仍合法，以便建立只包含测试或内部用途的包。
7. 作为包作者，我希望省略 modules 或 executables 时仅使用固定候选入口，以便目录中新增无关文件不会意外产生公开能力。
8. 作为包作者，我希望显式空模块或程序清单关闭自动发现，以便明确声明没有该类公开能力。
9. 作为包作者，我希望非空显式清单完全替代自动发现，以便清单之外的候选文件不参与决策。
10. 作为包作者，我希望多个自动模块入口同时存在时报歧义，以便工具不按隐含优先级选择错误入口。
11. 作为包作者，我希望显式入口无效时直接失败，以便默认入口不会掩盖配置错误。
12. 作为包作者，我希望单项显式产物可省略名称并使用包名，以便简单配置保持简短。
13. 作为包作者，我希望多项显式产物逐项命名，以便运行选择和公共接口不依赖文件名猜测。
14. 作为包作者，我希望模块与程序可以跨类别同名，以便同一产品能够同时提供导入和运行能力。
15. 作为包作者，我希望同类名称或入口重复时明确失败，以便结果不由声明先后决定。
16. 作为包作者，我希望名称非法时给出错误而不自动改写，以便公开名称不会在工具中悄悄变化。
17. 作为包作者，我希望含连字符的包名可配合显式合法模块名使用，以便保留包身份同时满足导出命名规则。
18. 作为包作者，我希望 Unicode 描述、选项值和文件路径得到保留，以便源码布局不受 ASCII 标识符规则误伤。
19. 作为包作者，我希望省略字符串与显式空字符串有不同结果，以便缺省行为不会掩盖错误的空名称或路径。
20. 作为包作者，我希望 workspace 的省略和显式空对象得到区分，以便空工作区仍能表达真实组织意图。
21. 作为包作者，我希望内部省略标记无需出现在配置中，以便普通数组就能表达自动、禁用和显式清单。
22. 作为包作者，我希望声明只暴露用户字段，以便运行时根路径、已解析修订和派生路径不会混入配置。
23. 作为依赖使用者，我希望每条引用显式选择 path、git 或 workspace，以便来源不会由名字或目录巧合推断。
24. 作为依赖使用者，我希望同名工作区成员不能覆盖 Git 来源，以便开发环境和安装环境使用相同来源语义。
25. 作为依赖使用者，我希望相对 path 以声明包根为基准，以便改变命令工作目录不改变依赖。
26. 作为本地开发者，我希望普通 path 可引用兄弟包，以便本地协作不强制纳入同一工作区。
27. 作为依赖使用者，我希望明确选择来源中的包目录和模块导出，以便引用多包仓库时不依赖包名搜索。
28. 作为依赖使用者，我希望一条来源引用可平铺选择多个包的模块，以便无需复制提供方的仓库组织结构。
29. 作为依赖使用者，我希望唯一公开模块可简写，以便简单引用保持简洁。
30. 作为依赖使用者，我希望零模块、多模块或纯工作区不能被简写猜中，以便扩展提供方时出现明确诊断。
31. 作为依赖使用者，我希望依赖引用名与导入名分离，以便配置项命名不改变源码导入接口。
32. 作为依赖使用者，我希望通过 alias 显式解决导入冲突，以便同时使用导出名相同的提供方。
33. 作为依赖使用者，我希望同一实际模块的重复引用被拒绝，以便不同别名不会绕过身份检查。
34. 作为依赖使用者，我希望不同来源或修订的同名包可以并存，以便在明确别名下表达真实依赖差异。
35. 作为包作者，我希望提供方自行声明所需依赖，以便消费方不必复述完整传递依赖图。
36. 作为包作者，我希望传递依赖不自动成为本包可直接导入的模块，以便缺少直接依赖能够及时暴露。
37. 作为模块作者，我希望同包公开模块可以相互引用，以便拆分公共接口不改变包的组织单位。
38. 作为依赖使用者，我希望依赖环报告完整链路，以便定位需要调整的包关系。
39. 作为 Git 包作者，我希望内部 workspace 引用使用提供方检出内的工作区，以便不受消费工程成员影响。
40. 作为 Git 包作者，我希望内部 path 可引用同检出的非成员兄弟包，以便来源身份与成员资格分别成立。
41. 作为 Git 包使用者，我希望内部引用不能越出检出根，以便来源不会隐式退化成消费机器上的任意目录。
42. 作为依赖使用者，我希望 Git 的 branch、tag、rev 互斥且与包版本元数据分开，以便修订选择只有一处权威配置。
43. 作为依赖使用者，我希望未写 Git selector 时使用仓库默认分支，以便简单引用不要求预先查找分支名。
44. 作为开发者，我希望普通构建复用有效的已解析修订，以便远端分支移动不改变本次构建选择。
45. 作为开发者，我希望只改引用名、alias 或模块清单时不追新提交，以便接口选择与版本更新分开控制。
46. 作为开发者，我希望 update 显式刷新所选消费包的完整 Git 依赖图，以便更新操作有清楚的范围。
47. 作为工作区维护者，我希望更新一个成员不改写其他成员的解析选择，以便共享缓存不等于共享版本决策。
48. 作为开发者，我希望共享提供方源码的不同工程各自记录传递依赖选择，以便一个工程的更新不影响另一个。
49. 作为离线开发者，我希望有效选择和完整缓存允许离线构建，以便工作不依赖远端可达性。
50. 作为离线开发者，我希望缺状态时只对缓存齐全的完整提交建立选择，以便工具不会猜测浮动引用。
51. 作为离线开发者，我希望缺内容、短修订或浮动选择缺记录时明确失败，以便失败不会被隐式联网或替换版本掩盖。
52. 作为开发者，我希望解析失败保留旧状态但报告本次失败，以便不存在半更新或虚假成功。
53. 作为开发者，我希望解析成功后的编译失败不回滚已经选定的修订，以便解析和编译结果有独立清楚的边界。
54. 作为开发者，我希望损坏或不可读的状态明确报错，以便它不会被误当首次解析而改变修订。
55. 作为开发者，我希望清理源码内容缓存不删除工程选择，以便重新下载仍取得同一修订。
56. 作为开发者，我希望移动工程根会建立新解析上下文，而只改变 cwd 不会，以便状态身份不按包名猜测迁移。
57. 作为开发者，我希望 XDG 内容缓存和状态目录的配置、回退及写入失败有固定规则，以便不同平台保持可预测行为。
58. 作为工作区维护者，我希望 members 支持明确目录和单层通配，以便集中维护成员列表而不递归纳入未知工程。
59. 作为工作区维护者，我希望 exclude 排除目录及候选子树，以便隔离实验包和独立嵌套工作区。
60. 作为工作区维护者，我希望根包自动成为成员且不能被排除，以便根包身份不会随成员列表丢失。
61. 作为工作区维护者，我希望重叠成员匹配去重，以便多个组织规则可以同时存在。
62. 作为工作区维护者，我希望独立嵌套工作区不能被外层重复收录，以便每包只有一个所属工作区。
63. 作为开发者，我希望未收录或被排除的包仍可独立运行，以便目录位于工作区内不等于具有成员资格。
64. 作为开发者，我希望从源码子目录向上定位最近声明，以便不用返回包根才能执行命令。
65. 作为开发者，我希望最近声明无效时立即报错，以便工具不会跳过错误并执行上层工程。
66. 作为工作区维护者，我希望默认成员与成员全集分离，以便根命令只操作日常需要的包。
67. 作为开发者，我希望在成员内默认只选择当前成员，以便根默认集合不扩大局部命令的范围。
68. 作为开发者，我希望使用 --workspace、-p 或 --package-path 显式选包，以便从一个入口处理全体、单包或多个包。
69. 作为开发者，我希望同名成员可通过工作区相对路径消歧，以便不必为了加入工作区而改包名。
70. 作为开发者，我希望冲突参数、未知包和零选包在执行前失败，以便没有部分命令被提前运行。
71. 作为程序作者，我希望 run 先选定唯一包再选择程序，以便不根据其他包是否有程序猜测我的意图。
72. 作为程序作者，我希望 default_run、显式程序名和唯一程序规则决定运行对象，以便不再依赖首项或包同名回退。
73. 作为开发者，我希望 run 只编译所选程序并原样传递分隔符后的参数，以便不构建无关程序且不损坏运行参数。
74. 作为模块作者，我希望没有程序时 build 校验声明和依赖后清楚报告无程序，以便成功不被误解成所有模块已完成类型检查。
75. 作为测试作者，我希望没有公开产物仍能执行测试，零测试或过滤零匹配也明确报告，以便测试用途不依赖公开程序。
76. 作为测试作者，我希望父包扫描在下级包或工作区声明处停止，以便成员、排除包和依赖测试不会混入父包。
77. 作为工作区维护者，我希望同一测试过滤条件逐包应用并汇总，以便批量测试结果能归属到具体包。
78. 作为工作区维护者，我希望批量操作稳定排序并在首个失败停止，以便已完成、失败和未执行范围都可观察。
79. 作为插件作者，我希望插件通过公开模块提供唯一入口，以便一个包能够同时提供多个插件模块和普通 API。
80. 作为插件使用者，我希望独立 plugins 来源声明即可启用插件，以便不需要重复写普通依赖或依赖成员名猜测。
81. 作为插件使用者，我希望内置和外部插件引用明确区分，以便外部同名包不能覆盖内置能力。
82. 作为插件使用者，我希望省略插件清单用默认、空清单禁用、非空清单完全替换，以便实际执行插件与配置一致。
83. 作为插件作者，我希望未知选项、重复键和无效值在 hook 前失败，以便错误配置不会先产生构建副作用。
84. 作为插件使用者，我希望插件兼容性独立于包版本和 Git selector 检查，以便不必填写重复版本约束。
85. 作为插件使用者，我希望同一实际插件只启用一次，以便不同名字或配置不会造成重复执行。
86. 作为插件使用者，我希望固定阶段顺序及同阶段清单顺序决定执行，以便无需优先级或自动排序系统。
87. 作为插件作者，我希望注册替换、丢弃和辅助源码形成派生视图，以便改变编译输入而不修改包声明。
88. 作为插件使用者，我希望所有输出位于消费工程私有派生目录，以便共享检出和包源内容保持只读。
89. 作为插件使用者，我希望每次只消费本轮注册的输出，以便旧文件或未登记的生成物不会意外进入编译。
90. 作为插件作者，我希望替换文件保留逻辑源路径，以便导入、诊断和测试归属指向原包内容。
91. 作为插件使用者，我希望派生输出冲突直接失败，以便插件顺序不会悄悄决定哪个结果获胜。
92. 作为包作者，我希望插件不能修改身份、产物、依赖或工作区声明，以便构建不会改变已经校验的模型。
93. 作为插件使用者，我希望插件只在各所选包自身启用，以便根配置、依赖包和未选成员的插件不会自动运行。
94. 作为程序作者，我希望同包多程序共享一次插件准备和派生视图，以便 run 不因前置 build 或目标数重复启用插件。
95. 作为插件使用者，我希望外部工具与配置失败归为插件错误，以便通用包声明不扩张为工具任务图。
96. 作为包作者，我希望尚不存在的公开入口要求先由独立脚本生成，以便普通入口校验不被插件隐式放宽。
97. 作为旧配置作者，我希望逐字段迁移指南说明保留、改名和删除，以便手工迁移时不遗漏行为变化。
98. 作为旧配置作者，我希望错误指出不支持的字段和可用替代，以便新旧配置混写不会被部分接受。
99. 作为工作区维护者，我希望根包和所有成员声明协同迁移，以便新版工具能完成整工作区校验。
100. 作为依赖使用者，我希望不兼容提供方被报告在实际引用链上，以便我明确选择兼容修订而不是工具自动追新。
101. 作为工具安装者，我希望 Juice 可执行文件与配套模块一起交付、升级和回退，以便声明求值不依赖其他安装目录。
102. 作为工具安装者，我希望缺失或错配发布物明确失败，以便工具不会从全局位置寻找替代并掩盖混装。
103. 作为维护者，我希望源码自举、配套发布和仓库外独立安装都通过验证，以便开发环境成功能够转化为可分发产品。
104. 作为文档使用者，我希望完整示例区分草案、预期和实际运行证据，以便不会把未实现接口当成已经可用。
105. 作为维护者，我希望验收优先使用临时本地 Git 仓库并覆盖两类文件系统，以便结果不依赖公网变化或单一平台。
106. 作为维护者，我希望本次声明变更与独立的 Testing 迁移工作保持边界，以便不会借规格整理暗中改变另一 effort 的决定。

## Implementation Decisions

1. **公开声明接口。** 保留现有 Juice 公共模块和唯一 PACKAGE 值，公开类型仍为 Package；workspace 是普通嵌套字段。Package 的用户字段为 name、version、description、modules、executables、dependencies、plugins、workspace、default_run。不增加 Manifest/Some/Configured_List 包装、用户 presence 开关或独立 WORKSPACE 入口。辅助常量与纯编译期表达式允许，只有 PACKAGE 参与声明读取；框架不在求值阶段调度插件或构建脚本。

2. **包存在性。** 包身份或能力字段任一显式出现时，name/version 必须同时合法；显式空的能力列表仍算包配置。只有 workspace 存在而包字段全部省略时为纯工作区，不建立根包、不为根自动发现产物或启用默认插件。显式空 workspace 代表已声明空工作区；全部省略为错误。Package 的声明容器不等于必须存在一个包。

3. **省略状态。** 用户继续写普通字符串、数组、嵌套结构；类型使用不与合法值相交的内部保留默认标记，加载器把求值后数据转换为省略、显式空或非空状态。数组零长度和空字符串不能作为省略判据。手工伪造或复制内部标记不属于受支持输入，不承诺恢复任意源码初始化历史；标记不成为公开配置值。依据独立 Jai 实验已确认表达机制及碰撞限制，但当前完整 Juice 接口尚未实施。

4. **模块与程序。** 移除包级 LIB/BIN 互斥，modules 与 executables 独立取省略、空、非空状态。自动发现只使用已确定的固定入口约定；模块零候选为零项、唯一候选采用、多个候选歧义，程序仅有一个固定候选。非空显式清单不追加自动项，也不检查未采用候选的歧义；空清单为零项。显式 item.entry 必填，单项 item.name 可省略取包名，多项必须逐项命名。entry 是包内现存的普通 Jai 文件，显式错误不回退；生成公开根入口须在重新发现声明之前完成。

5. **字段默认矩阵。** modules/executables 省略为自动、空为禁用；dependencies 省略或空均为无依赖；plugins 省略为内置 load/test-block、空为无插件；members 省略或空均为零显式成员，exclude 省略或空均为无排除；default_members 省略用位置默认、空表示没有默认选择；default_run 省略按程序数选择，显式值必须匹配。description 允许空；options 省略或空使用插件默认。显式空 name/version/entry/引用 path/alias/selector/default_run 等不等同于省略，option value 的空值由对应 schema 决定。

6. **名称语法与作用域。** 包名、依赖引用名、插件 ID 使用 ASCII 字母或数字起始，后续允许 ASCII 字母、数字、点、下划线、连字符；模块名、程序名、导入名/alias、options key 使用 ASCII 字母或下划线起始，后续只允许字母、数字、下划线。比较键统一 ASCII 大小写不敏感，保留原拼写，不修剪或自动改名。同类产物名称、依赖引用名在各自包内判重；模块和程序跨类同名允许。options 在所属插件内判重，不跨插件合并。工作区不同目录可有同名包。Unicode 可用于描述、选项值和路径，不参与标识符转写。自动名称仍须合法，含连字符包名不能自动转成模块/程序名。

7. **原始输入与内部状态。** 声明读取/求值模块产生原始字段和可取得的定位信息；规范化模块产生已校验的逻辑路径、实际包根、名称及来源；依赖解析状态持有上下文、Git 修订和对应声明关系。dir、物理绝对路径、已解析修订和派生路径不回填公开声明。实现可复用现有内部类型或重构，但不能以旧互斥包类型限制新模型，也不能把全局共享源码位置当作工程上下文。

8. **路径规则。** 保留原始输入，内部统一分隔符、消解点段，再做字段相应根范围和物理身份检查。包内入口、工作区目录规则和来源内模块选择都拒绝绝对或规范化后越界输入；普通本地 source.path 相对声明包，可指兄弟目录，该来源确定后成为模块选择根。Git 内部相对引用只能留在检出内。受约束路径链不接受符号链接/junction，入口必须为普通文件。Windows 大小写别名按同一路径处理，大小写敏感文件系统按实际身份处理；不得把 ASCII 名称折叠用于 Unicode 路径。成员匹配重叠去重，同类产物同入口失败，依赖同模块重复失败，三者不可混用。

9. **显式来源类型。** 普通依赖与插件来源复用互斥的 PATH/GIT/WORKSPACE 类型标记与载荷，缺类型、多来源或载荷与类型不符失败。PATH 定位声明包相对来源根；GIT 定位所选提交的检出根；WORKSPACE 定位声明包实际所属工作区且提供方必须是成员。缺声明、非法包目录或导出不做包名搜索、注册中心回退或同名成员覆盖。Git 的地址/引用/提交校验使用 Git 语义，不套用包名称或版本范围语法；失效或歧义解析不能更换来源。

10. **模块选择接口。** Dependency.name 为消费包内引用名，source 负责内容定位，modules 为平铺模块选择；每项 path 是来源根内包目录，name 是提供方导出，alias 为可选最终导入名。path 省略为来源根，name 省略只接受该包恰好一个导出，alias 省略沿用导出名。整个 modules 省略采用来源根唯一模块简写；根无包、零/多模块分别失败。普通依赖显式空 modules 报能力不匹配。提供方必须有有效包声明，消费方不能指定源码入口绕过导出清单。

11. **身份与可见性。** 本地 path/workspace 各自先验证来源资格，再按规范化包目录识别同一包；Git 包身份包含仓库来源、已解析提交与仓库内包位置，模块再加导出身份。同一实际模块在消费包内最多被选择一次，引用名、alias 或路径拼写不同不豁免；不同来源/修订的同名包可在明确别名下并存。最终导入名不得覆盖本包模块、其他直接导入或编译器标准模块。提供方包内模块可互相使用，传递依赖不泄漏为最外层直接导入。普通依赖为包级统一清单，模块、程序和测试共用；包级直接依赖图须无环并报告完整环路。

12. **Git 提供方边界。** 外部 Git 包内部的 workspace 归属只在本检出内寻找，不能借消费工程的成员或越出检出根。同检出内部 path 可访问非成员兄弟包，但保留 Git 来源及提交身份；跨仓库引用必须另有显式 Git 来源。普通本地开发引用仍保留兄弟目录能力。共享检出只读，依赖编译和派生内容放消费工程私有区域。

13. **Git 修订与工程上下文。** branch/tag/rev 至多一个，全部省略为默认分支，显式空值失败；不新增依赖版本范围、提供方包名断言或锁文件。有效已有记录由普通 build/run/test 复用，不访问远端追新；只改引用名、alias、模块清单不换提交，缺导出报错。已选内容缺失只补该提交，不换最新分支。来源/selector 改变、记录缺失或新上下文才重新解析。更新作用于所选消费包的完整直接/传递 Git 图，不提供单条依赖定向更新。

14. **上下文隔离与离线。** 选择记录区分发起消费工程、声明包和来源 selector；同工作区成员可独立选提交，两个工程共享提供方源码也不共享其传递选择。工程移动/复制到新规范化根产生新上下文，不按包名搬迁状态；只改 cwd 不变。离线已有选择且全部内容齐全可用；无记录时仅完整提交且全图内容齐全可建立选择，浮动/短修订或缺内容失败。update 与 offline 冲突；不隐式联网，也不从共享缓存 HEAD 或其他上下文猜版本。

15. **缓存与状态原子性。** 内容缓存与工程选择状态分目录，遵守 XDG 优先及平台默认契约。相对 XDG 值警告并回退，有效配置不可写失败，不换 cwd/临时位置；无法确定可靠默认根也失败。清内容不清状态，损坏/不可读状态不能视为缺失。每消费上下文在完整获取、声明、模块选择、冲突、环及适用插件校验成功后整体发布解析选择；失败保留旧状态但操作失败。后续 hook、派生或编译失败不回滚已成功解析。下载内容和部分输出不代表成功；批量操作不是跨成员事务。

16. **工作区发现。** members 支持工作区内相对明确目录及不跨目录分隔符的单层星号匹配，不支持递归或其他模式；明确成员目录无效或模式无匹配失败。展开后应用 exclude，排除命中目录及候选子树，无匹配 exclude 合法；保留项须有有效包声明，再按实际目录去重。根包自动加入且不可被排除；纯工作区没有隐含成员。独立内层工作区形成归属边界，外层命中其根或成员且未排除时失败，不静默跳过/展开。一个包至多属于最近合法工作区，未收录或被排除者作为独立包，不继续寻找更外层归属。

17. **命令定位与默认对象。** 从 cwd 向上找最近声明，遇无效声明即失败，不跳过到上层。独立包/非根成员及其子目录默认只选当前包；根包工作区从根位置默认用 default_members，省略则根包；纯工作区根省略默认配置则选全体成员。未进入其他包的根下目录沿用根规则。default_members 只接受明确成员目录，无通配，空清单表示根调用没有默认选择。最终零包均失败，与包内零程序/零测试分开。

18. **显式选包。** --workspace 选择当前工作区全体成员含根包，与其他选择参数互斥；-p/--package 按唯一包名，--package-path 按所属工作区根相对包目录。名字和路径可重复/混用，按包身份去重，显式集合替代默认。重名列候选目录，未知/非成员/跨内层工作区失败。独立包不支持 --workspace，名字或路径只能选自己。完整选包和命令基数在执行前校验；run 必须恰好一包，不筛掉无程序包来猜测。

19. **命令行为。** build 编译所选包全部程序；零程序仍校验声明和依赖后成功提示无可执行产物，不承诺单独类型检查未使用模块。run 在唯一包内按显式程序、合法 default_run、唯一程序顺序选择；零程序或多程序无选择失败，无效 default_run 始终是声明错误。只编译所选程序及所需依赖，分隔符后参数原样转交。test 无需公开产物，过滤条件逐包应用，零测试/零匹配成功报告；声明/依赖/实际编译错误不能被过滤隐藏。update 只刷新解析图，不编译或执行测试。

20. **批量与测试包边界。** 先校验工作区全体成员声明，只有被选包及其实际依赖图进入获取/执行；未选成员声明错误阻止操作，无关远程依赖不可取得不单独阻止。按规范化工作区相对目录稳定排序逐包执行，首个失败停止，已成功包不回滚，报告已完成/失败/未执行范围。每包测试扫描遇下级声明即剪除该子树，不要求其是登记成员；被排除包、未登记包、嵌套工作区和依赖测试不会混入父包。

21. **插件接口与选择。** 插件通过已声明公开模块提供，不是第三类包产物，零公开模块包不能作为插件提供方。每个被选模块有且只有一个插件入口；零入口报能力缺失、多入口歧义，不扫描其他模块/传递依赖猜测。外部插件启用项独立选择来源、包位置、模块和配置，不要求重复普通依赖；普通业务若需 API 则选提供方另一公开模块。同一插件模块再次被普通依赖选择失败。同一实际插件不允许通过不同名字、来源拼写或配置启用多实例。

22. **插件默认、配置和阶段。** 内置引用与外部来源互斥，保留内置 load/test-block。省略 plugins 启用两者；显式空禁用全部；显式非空仅清单项，不因缺转换能力补默认。options 由插件 schema 定义默认值、解析和校验，重复/未知键、必填缺失或非法值在 hook 前失败；省略/空 options 都用默认，不等于禁用插件。入口兼容性单独检查，不重复用户插件 version。固定生命周期阶段决定先后，同阶段按清单顺序；无优先级、插件间 before/after 排序图或自动重排。失败中止当前包。

23. **插件执行范围。** 各被选包使用自身插件声明和私有状态，根/工作区配置不继承给成员，依赖及未选包插件不自动获取或执行。一次包操作完成一次插件准备和所需派生视图，各插件贡献仍在其所属阶段执行；不能因为 build 前置链或多个程序重复启用包级插件。run 复用该包视图但只编译所选程序，test 使用本包视图。update 不因解析插件来源而执行构建 hook。外部工具由对应插件 options 声明或探测，缺工具、缺配置或执行失败均为插件错误。

24. **派生视图接口。** 保留现有阶段输出接口并补齐显式辅助源码注册：substitute 映射已有逻辑输入到派生文件，drop 排除输入，generated 注册辅助 Jai 文件。物理输出限于消费工程私有派生区，包源和共享检出只读；本轮全新视图只消费本次注册输出，不递归扫描派生目录、不用旧结果掩盖失败。替换仍以逻辑包内路径解析导入、报告诊断和归属测试，物理路径仅用于读取。重复替换、重复辅助路径、覆盖保留源码或同一路径 drop/substitute 冲突全部失败，不按顺序覆盖。创建、清理、写入或注册失败中止当前包。

25. **插件能力边界。** 插件不修改包名、公开模块/程序、入口声明、依赖、插件清单、工作区成员或命令程序选择。现存入口可换编译视图，辅助文件不能自动成为公开根入口。尚不存在的公开入口先由用户独立脚本生成，再重新进行声明发现；build_script 字段退出自动调度。保留既有 test-block、lint 和生命周期贡献的职责，本规格不因“派生视图”而删除插件观察能力，也不增加通用任务图。

26. **校验与诊断。** 按求值、结构、字段/省略状态、名称/路径/来源规范化、语义、入口/文件系统检查分阶段处理，有前提才继续下游。远程提供方先完成可本地判定的声明检查，取得内容后必须在发布解析状态和执行构建 hook 前完成对应校验。阶段可收集独立错误，失败不发布部分可执行规范化结果。报告声明文件、字段/条目、原因；可靠时给源坐标，否则使用稳定字段/列表顺序而不伪造位置，成员按路径排序。Jai 编译器可先拒绝未知成员/类型，保留其诊断并补准确迁移指引；不声称加载器能拦截所有编译器错误。求值不承诺安全沙箱。

27. **修改的现有模块及职责。** 公共声明面、求值协议/读取、产物解析、工作区发现/选包、依赖解析/导入准备、插件准备/宿主/派生输出、命令编排、自举和模块发布共同接入以上契约。复用既有命令 lifecycle 会话、目标布局、进程与诊断接口；避免每条命令重复实现来源或默认值。声明/解析层提供校验后的对象，命令层消费明确选择；包装过多的公共构造器与通用无约束状态容器不作为解决省略状态的接口。

28. **迁移与交付。** 首版人工迁移，删除 type、targets/main_file、旧依赖 version/package 搜索、旧插件成员名猜测/version 和 build_script 等受替代字段/行为；workspace 保留。不得以新字段共存部分接受旧配置，也不自动推断 path/git/workspace。根与全部成员声明一起迁移，实际使用的外部/传递依赖和插件须兼容；错误给引用链，作者显式选择兼容修订或补声明，不自动追新。可执行文件和配套模块构成完整安装单元，内部检查声明类型、协议及插件入口兼容；缺失/混装失败，无其他安装目录回退，无用户兼容开关。

29. **文档与关联 effort。** 产品规格统一新行为并移除冲突旧描述；迁移指南提供逐字段对照、完整目录/声明/命令/预期及反例，并保留决策追溯。区分未来接口草案与可运行示例，最终文档使用已交付的公共声明写法。另一张 Testing 迁移地图的组织变更不纳入本次实施，现有测试和插件集成保持可用；不得以本规格默改其已关闭决定。

## Testing Decisions

1. **主要验收界面已获用户确认。** 以真实 Juice CLI 操作临时工程为主：输入是包声明、源码、命令、cwd 和受控环境，观察退出码、诊断、产物行为、允许的导入范围及解析状态变化。源码自举、配套发布和仓库外独立安装是同一外部接口的三种交付配置，不新增三套业务测试 API。沿用迁移交接票 Q4/Q7 的确认。

2. **好测试验证行为。** 断言被选包/程序、导入成功或明确拒绝、实际修订、无关上下文未变、错误没有触发后续编译/源码回写等承诺。不要锁死内部结构成员顺序、哈希算法、哨兵字节、临时目录随机名或私有协议实现；已属于发布契约的布局与兼容标记可以校验其行为。旧测试使用过字符串钉住内部文本，不代表新规格要求继续为未公开细节加锁。

3. **优先复用现有测试入口。** 现有子进程帮助函数可带指定 cwd 执行 Juice，临时区可承载完整工程；自举用例已经验证发布模块和产物版本；安装布局用例复制可执行文件与模块树，验证没有旁路源码时仍可测试；真实 jaix 安装用例验证 build/test、生成程序行为和缺插件支持模块失败。沿这些用例扩展，避免新建仅供测试的清单求值器或独立解析器副本。准确定位及现有验证限制见 Further Notes。

4. **补充层次受现有接口约束。** 清单读取、归一化、工作区和插件宿主已经有函数级测试及进程替身；可在这些现有接口上定点触发坏协议、写入失败、宿主崩溃、缓存缺失等难以稳定构造的条件，再以 CLI 关键链路证明集成。需要注入失败时使用现有存储/进程边界，不为每个内部字段新增 seam。新功能验收不能只构造内部对象而绕过用户的普通声明写法。

5. **示例 E01–E10 是必须交付的用户输入。** 每例包含目录树、完整声明、调用位置/命令、成功或失败预期以及关联规则；覆盖最小程序、仅模块、模块加多程序、纯工作区、根包工作区、本地与工作区依赖、Git 上下文、lint、jaix 与普通 API、零公开产物。最终用配套发布的真实公共模块编译这些声明，覆盖省略、显式空、非空，而非只验证孤立哨兵实验。

| 验收组 | 外部可见断言 | 对应用户故事 |
|---|---|---|
| A01 声明与旧字段 | 唯一简单入口、纯工作区判定、三态/空值、旧字段拒绝、workspace 保留 | 1–22、97–99 |
| A02 工作区与 Git 同名 | 同名成员不覆盖 Git；名称选择歧义不改变来源 | 23–24、34、39、68–69 |
| A03 来源资格与去重 | path/workspace 各自合法后，同一模块重复失败、不同导出可用 | 25–33、40–41 |
| A04 传递可见性 | 提供方自声明依赖，同包模块可用，传递模块不能直接导入，环完整报告 | 35–41 |
| A05 普通引用与插件 | 不自动导入或启用；同插件模块双重选择失败、独立 API 合法 | 79–85 |
| A06 插件默认与配置 | 省略/空/显式不同，缺项不补默认，坏 options 在 hook 前失败 | 81–86 |
| A07 多程序与批量插件 | 包级准备一次，各包隔离；run 只编译目标，依赖插件不自动执行 | 71–73、78、86、93–94 |
| A08 派生输出 | 只读取本次注册内容、逻辑路径稳定、输出冲突失败、源码只读 | 87–92、95–96 |
| A09 离线解析 | 有记录复用，完整提交无记录例外，浮动/短修订/缺内容拒绝 | 42–45、49–51 |
| A10 更新与失败 | 全图刷新、上下文隔离、失败保旧、已成功成员不回滚、离线更新冲突 | 46–48、52–54、78 |
| A11 内容与状态 | 清缓存不清选择、损坏报错、移根新上下文、cwd 不改上下文、XDG 回退 | 55–57 |
| A12 提供方内部来源 | Git 内工作区不借消费者、非成员内部 path 可用、检出越界失败 | 39–41 |
| A13 成员校验与扫描 | 未选声明错误阻止操作、无关远程图不获取、下级包测试不混入 | 58–65、75–78、99–100 |
| A14 命令选择与零集合 | 默认/显式集合、歧义/零包失败、零程序和零测试区别、参数透传 | 66–78 |
| A15 跨文件系统路径 | 名称 ASCII 判重、物理大小写身份、链接拒绝、跨类别规则不同 | 14–20、61、105 |
| A16 完整安装 | 同版本配套在仓库外使用，缺模块/不兼容明确失败，无其他安装回退 | 101–104 |

6. **固定依赖实验环境。** 使用临时本地 Git 仓库构造分支移动、tag、完整/短提交、多包提供方和传递依赖，隔离 XDG 内容/状态根。记录首次解析、重复构建、显式更新、别名变化、缺缓存和损坏状态前后的可见结果。不得为了测试清理真实用户缓存或修改其已有工程选择；无需依赖公网分支最新状态。

7. **三条实施验收路径均须通过。** 源码自举覆盖现有 debug/release 流程；配套发布检查运行物与声明/插件模块兼容；独立安装在仓库外临时工程完成求值、build/run/test 及相关 update/offline/负例。插件工具存在性按用例要求明确提供。必要用例跳过必须报告原因，不能作为通过；Windows 与大小写敏感文件系统分别执行对应路径规则，不把单平台成功推断为跨平台成功。

8. **完整性和证据。** 每条关键规则关联故事、示例或验收组；原决策票的失败表继续作为补充输入，不要求用 A 组枚举所有笛卡尔积。报告提交、编译器版本、平台、命令/cwd、退出码、输出摘要及跳过项。规划票关闭、已有用例位置、旧行为测试通过、独立 Jai 实验与新实现全链通过分别记录，禁止互相替代。

## Out of Scope

- TOML/ZON/新 DSL，公开 Manifest/Some/模式包装，独立 WORKSPACE 入口，以及由用户填写的兼容性开关。
- 永久保留旧声明语义、静默兼容回退、自动改写清单、猜测依赖来源或自动选择迁移版本。
- 静态/动态二进制库产物、包注册中心/发布服务、版本范围求解、锁文件和跨机器浮动来源的完全可复现保证。
- 按模块或测试/构建用途再拆普通依赖清单，单条依赖定向更新、成员依赖隐式注入及工作区级依赖/插件/构建配置继承。
- 递归成员通配、通用构建任务图、自动插件排序、同一插件多配置实例、插件生成尚不存在的公开根入口。
- 把 Jai 求值器变成安全沙箱、对手工伪造内部标记追踪初始化来源、复杂 OS 权限隔离或通用插件宿主扩展。
- 执行独立 Testing 迁移地图中的模块搬迁、批量修改兄弟仓库，或借本规格重写无关 clean/help/version 的行为；新增命令的必要帮助信息除外。
- 发布到用户环境、自动清除或搬迁用户的真实解析状态；验收只操作受控临时工程和安装副本。

**固定文件与目录契约。** Implementation Decisions 避免绑定实现文件，以下集中记录用户可见、已确认的路径约定和交付落点：

| 契约 | 固定约定 |
|---|---|
| 声明入口 | `package.jai`，`#import "Juice"`，唯一 `PACKAGE :: Package.{...}`；`workspace` 嵌套其中 |
| 自动模块候选 | 包根 `module.jai` 或 `src/module.jai`；二者同时存在为歧义 |

| 内容缓存 | 有效绝对 `$XDG_CACHE_HOME/juice` 优先；非 Windows 默认 `$HOME/.cache/juice`；Windows 默认 `%LOCALAPPDATA%/juice/cache` |
