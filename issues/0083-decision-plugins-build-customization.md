## Question

前置为 [依赖解析决定](0081-decision-dependency-identity-sources.md#resolution) 和 [工作区选包决定](0082-decision-workspace-members-selection.md#resolution)。

在显式依赖和独立工作区模型下，插件的获取、身份、启用、配置及顺序怎样声明，构建脚本的职责如何与纯声明分开？

需决定插件是否引用已声明依赖还是保有独立来源面、版本与包身份在哪里唯一声明、工作区成员身份与插件启用是否独立；空插件列表与内置默认插件含义、显式列表是否替换/追加、排序及配置错误规则。对现有 build_script 字段应明确支持契约、删除或另设扩展，而不是接受却不消费。

[提供方模型](0080-decision-package-products-defaults.md#resolution) 采用包内现存源码入口。本票须明确生成入口/插件替换源是否另有显式声明渠道，以及生成与入口存在性校验的先后关系；若不支持须明确拒绝，不静默绕过普通入口规则。插件包公开模块与可发现插件入口之间的关系也要结合多个模块导出的能力核对。

[依赖解析决定](0081-decision-dependency-identity-sources.md#resolution) 已确认：普通导入依赖必须选择至少一个公开模块，modules = [] 不会隐式获得工具或插件能力。本票须明确非普通导入用途的声明与能力校验，以及零公开模块的包是否可用于这些用途；不能用空模块列表代替启用声明。依赖决策另已要求普通模块依赖暂为包级统一清单，不新增 test-only/build-only 依赖字段；插件或构建专用来源必须有本票定义的显式用途。

依赖讨论第十三轮已确认共享 Git 检出不能被构建回写。本票的生成源码、插件改写和构建输出须有工程私有派生位置；明确如何提供给编译器，不能把共享缓存目录当作可写工程根。该使用约束不要求在本轮增加复杂的系统权限机制。

用现有 lint/jaix 成员插件和普通非插件依赖举例；复杂构建流程留给脚本或插件，但不因此设计通用任务图。完成条件：各字段职责、解析/启用顺序和不支持的组合明确，无重复身份配置和隐式激活。

工作区交接以 [工作区选包决定](0082-decision-workspace-members-selection.md#resolution) 为准：本票需把插件获取/启用、生成入口及构建脚本的阶段，接入整工作区声明校验与所选包执行的契约。明确未选成员只能参与声明校验时如何避免启动其构建流程；run 只执行所选程序所需的构建，批量命令按包执行且失败停止。派生内容和插件配置须保持消费包上下文隔离。工作区级插件/构建配置继承不在本轮范围，成员身份不能隐式启用插件。

### Q5 待确认：插件来源与普通依赖的具体示例

前置 [依赖身份、显式来源与可复现解析](0081-decision-dependency-identity-sources.md#resolution) 规定：同一消费包对同一实际模块最多选择一次，跨 Dependency 或不同 alias 的重复选择均失败。因此“插件有独立来源面”不能再配套“同一个插件模块另外作为普通依赖选择”这一说法；下面区分可行组合。

以下是语义草图，字段的最终 Jai 类型和字面量由 [声明表达与校验契约](0084-decision-declaration-evaluation-validation.md) 决定。`source` 复用 path/git/workspace 三选一，模块选择沿用 `modules[].path` 与 `modules[].name` 的职责。

提供方可以把插件入口和普通 API 分成两个公开模块：

```text
packages/juice-plugin-jaix/package.jai
  modules = [
    { name = "Jaix_Plugin_Test_Block", entry = "module.jai" }, // 含唯一 @juice_plugin 入口
    { name = "Jaix_Config_API",        entry = "api.jai" },    // 普通代码可导入
  ]
```

方案 A（本票的推荐）：插件启用项直接选择插件用途来源；普通依赖只选择普通 API，二者不重复选择同一模块：

```text
app/package.jai
  plugins = [
    {
      source = workspace,
      modules = [{ path = "packages/juice-plugin-jaix", name = "Jaix_Plugin_Test_Block" }],
      options = [{ key = "config", value = "config.jai" }],
    },
  ]
  dependencies = [
    {
      name = "jaix-api",
      source = workspace,
      modules = [{ path = "packages/juice-plugin-jaix", name = "Jaix_Config_API" }],
    },
  ]
```

这里 `workspace` 只表示显式选择当前工作区成员；成员身份不会自动启用插件。若将插件移到 Git 来源，只替换 `source` 为带 URL 与 `rev` 的 Git 来源，仍选择明确的包目录和模块导出名；不需要把它复制进普通 `dependencies`。

方案 B（不是当前推荐，但可解决“业务代码必须导入同一个插件模块”）：普通依赖先选择插件模块，插件清单只引用这条已选依赖，不再重复声明来源/模块：

```text
  dependencies = [
    {
      name = "jaix-plugin",
      source = workspace,
      modules = [{ path = "packages/juice-plugin-jaix", name = "Jaix_Plugin_Test_Block" }],
    },
  ]
  plugins = [{ dependency = "jaix-plugin", options = [...] }]
```

方案 B 会让插件启用和普通导入共享同一模块选择，但需要新增“插件项引用已解析 Dependency”的语义，且插件能力仍必须显式启用。方案 A 则保持普通依赖和插件依赖两个小而清晰的接口，业务代码若需 API 应导入提供方另一个公开模块，不能重复选择插件入口模块。

Q5 请确认：采用方案 A，插件拥有独立来源选择面；同一插件模块不得再被普通依赖选择，业务 API 通过另一个公开模块提供。若必须让业务代码导入同一个插件模块，则改选方案 B。

### 第四轮：插件配置、派生视图与执行阶段

用户答复：`采用方案a`，确认 Q5。

本轮待确认以下契约：

**Q11 — 插件 options 采用插件自有 schema，省略和空 options 使用插件默认值？**

建议插件启用项的 `options` 只表达用户提供的键值；省略与显式空 options 均表示不覆盖插件默认值，不把空 options 解释为禁用插件。插件自己声明键、默认值、值解析与校验。重复键、未知键、缺少必填值或值格式错误，在任何 hook 执行前失败。

**Q12 — 插件只能产出工程私有派生视图，不得改写源文件？**

建议插件输出限定为三类结构化结果：已有源码相对路径到派生源码的替换、明确丢弃某个输入文件、以及工程私有目录中的辅助 `.jai` 文件。所有输出位于所选包的 `target/` 派生目录；共享 Git 检出和包源目录只读。普通 `entry` 先按包内现存文件校验，再允许插件替换其编译视图；插件不能凭空把辅助文件提升为公开模块/程序入口。是否同意？

**Q13 — 派生结果冲突一律失败，不按顺序覆盖？**

建议以下情况在编译前失败：两个插件替换同一输入、两个插件生成同一辅助路径、生成路径与保留源码路径冲突、同一路径同时 drop 和 substitute。插件清单顺序只决定合法的同阶段执行顺序，不决定冲突胜者。

**Q14 — 先完成全量解析与校验，再执行任意插件 hook？**

建议顺序为：工作区/所选包声明校验 → 所选插件来源与模块解析 → 插件入口/兼容性校验 → options 合并与校验 → 建立私有派生目录 → 按固定阶段执行 hook → 校验派生视图 → 依赖编译/目标编译。任一插件失败都使当前包失败，不继续编译；不因已有旧派生文件而跳过本轮插件。

**Q15 — 插件按所选包执行一次，根包不继承成员插件？**

建议每个被选包只加载自己的插件声明；工作区不继承插件，依赖包和未选成员的插件也不自动启用。批量命令按包分别解析、分别生成 `target/` 派生视图；同一插件在不同消费包上下文中可有不同配置和结果。

**Q16 — 外部工具由插件 options 指定，不增加通用 tools/task 图？**

建议插件可在自身契约内声明或探测外部工具，例如 jaix 的 `config`、`exe`；工具不存在、配置文件不存在或执行失败均是插件错误。package 声明不增加全局工具字段，也不把插件命令展开为通用构建任务图。是否同意？

### 第五轮：插件配置、派生视图与执行阶段

用户答复：`全部按推荐`，确认 Q11–Q16。

- `options` 由插件自有 schema 负责键、默认值、值解析和校验；省略与显式空 options 均使用插件默认值，不禁用插件。重复键、未知键、缺少必填值和格式错误在 hook 执行前失败。
- 插件输出只允许结构化的替换、丢弃和辅助 `.jai` 文件生成；全部写入所选包的工程私有 `target/` 派生目录，不改写包源文件或共享 Git 检出。普通 entry 先校验包内现存文件，插件不能把辅助文件提升为公开入口。
- 派生结果冲突一律失败：重复替换输入、重复生成辅助路径、生成路径覆盖源码、同一路径同时 drop/substitute，均不按清单顺序覆盖。
- 所有选中插件先完成来源、模块入口、兼容性和 options 校验，再建立派生目录并执行 hook；hook 失败即当前包失败，不继续编译，也不因旧派生文件跳过本轮插件。
- 每个所选包只执行自己的插件；工作区不继承插件，依赖包和未选成员不自动获取或执行。批量命令按包独立生成派生视图和保存状态。
- 外部工具由插件自己的 options 声明/探测；工具、配置或执行失败均为插件错误。不增加全局 tools 字段或通用任务图。

### 第六轮：派生视图接口与声明边界

用户答复：`全部按推荐`，确认 Q17–Q21。

- 辅助源码必须由插件以结构化结果显式注册；编译器不递归扫描 `target/`。辅助文件不能自动成为公开模块或程序入口；已有入口替换使用 substitute，不伪装成新入口。
- 源码替换保留逻辑包内路径，物理 `target/` 路径只作为读取位置；导入解析、诊断和测试归属以逻辑路径为准，插件不能用任意绝对路径绕过包边界。
- 每次包操作使用全新的插件派生视图；编译器只读取本次注册的输出，旧目录不参与扫描。派生目录创建、清理或写入失败均使当前包失败，不使用残留文件。
- 插件不能新增、删除或修改公开模块、可执行产物、依赖、插件清单、工作区成员、包名或入口声明。需要生成全新公开入口时，必须先由独立脚本生成，再重新进行包声明发现。
- 每个所选包在目标编译前执行一次插件；build 使用该视图构建全部目标，run 使用该视图但只编译所选程序，批量命令按包独立执行。插件不因多个程序重复执行，也不因依赖包存在而自动执行依赖包插件。

## Resolution

本票经用户多轮确认完成。下列内容确定 Juice 包声明中的插件来源、启用、配置和构建定制边界；仅完成规划决策，未修改生产实现。精确 Jai 结构体、三态字段表达、路径比较和状态编码交由 [Jai 声明表达、默认值与校验契约](0084-decision-declaration-evaluation-validation.md) 落实。

### 1. 插件模块与来源

- 插件不是第三类包产物。提供方通过公开 `modules` 暴露插件模块；包可以同时暴露普通模块和插件模块。插件模块必须满足 Juice 插件入口契约并有且只有一个插件入口；零公开模块的包不能作为插件提供方。
- 消费包通过独立的 `plugins` 来源选择面启用插件。每项明确选择 path、git 或 workspace 来源、来源内包目录、公开模块导出名及 options；不按插件名猜工作区成员，不把成员关系当作启用。
- 内置插件使用保留固定名；外部插件必须带显式来源，二者不能互相覆盖。省略插件清单时的默认内置集合为 `load`、`test-block`。
- 同一实际插件按来源身份/已解析修订、包目录和模块导出判重。路径写法、启用名或配置不同都不能绕过重复检查；首版不支持同一插件的多配置实例。
- 插件启用项不重复填写普通依赖的 `version`；Git 的 branch/tag/rev 由来源选择。插件加载时独立检查 Juice 入口兼容性，不兼容直接失败。
- 采用独立来源方案：同一插件模块不得再被本消费包的普通 `dependencies` 选择；这遵守 [依赖身份、显式来源与可复现解析](0081-decision-dependency-identity-sources.md#resolution) 的同一实际模块重复规则。提供方若需让业务代码使用 API，应另导出普通模块，由普通依赖选择。插件能力仍必须显式启用。

### 2. 启用清单与顺序

| plugins 配置 | 语义 |
|---|---|
| 省略 | 启用内置 `load`、`test-block` |
| 显式 `[]` | 不启用任何插件，包括内置插件 |
| 显式非空清单 | 只启用清单项；需要内置插件时也必须列出 |

不因清单缺少转换能力而自动恢复默认插件；源码不能编译属于显式配置的结果。工作区不继承插件配置，依赖包和未选成员不自动启用插件。

生命周期阶段有固定顺序；同一阶段按清单顺序执行。首版不提供插件优先级、before/after 依赖或自动重排。零/多插件入口、重复插件、未知内置名、来源无效、模块不提供插件能力和兼容性失败均在 hook 前诊断；插件失败停止当前包操作。

插件 `options` 由插件自有 schema 定义键、默认值、值解析和校验。省略或显式空 options 都表示使用插件默认值，不表示禁用插件。重复键、未知键、缺少必填值和格式错误在 hook 执行前失败。外部工具例如 jaix 的 `config`、`exe` 属于插件自己的 options；工具、配置文件或执行失败均为插件错误。package 声明不增加全局 tools 字段或通用任务图。

### 3. 构建定制与派生视图

普通模块/程序 `entry` 先按提供方包根校验为现存的包内 `.jai` 文件；插件不能凭空把生成文件提升为新的公开入口。首版不支持“只有 schema/config，构建时才生成公开程序根入口”的声明渠道；先由独立 `build.jai` 或其他外部编排生成入口，再重新执行包声明发现。旧 `build_script` 字段不再静默接受或调度，迁移时报告不支持/迁移错误；独立构建脚本仍可由用户直接调用处理复杂编排。

插件只能返回当前包构建的结构化派生视图：

- `substitute`：将逻辑包内已有源码路径映射到工程私有派生文件；
- `drop`：明确排除某个输入文件；
- `generated`：显式登记辅助 `.jai` 文件的逻辑路径和派生物理路径。

所有物理输出位于所选包的 `target/` 私有派生目录；共享 Git 检出、缓存内容和包源目录只读。编译器只使用本轮插件注册的输出，不递归扫描 `target/`，旧派生文件不参与当前操作。源替换保留逻辑路径用于导入解析、诊断和测试归属，物理路径只用于读取派生内容；插件不能用绝对路径越过包根。

两个插件替换同一输入、生成同一辅助路径、生成路径覆盖保留源码、或同一路径同时 drop/substitute，均为冲突错误，不按清单顺序覆盖。派生目录创建、清理、写入和输出注册失败均使当前包失败。插件不能修改包声明、公开模块/程序、依赖、插件清单、工作区成员或包身份，也不能把辅助文件变成公开产物。

### 4. 阶段与工作区执行

每个包的执行顺序为：

1. 按 [独立工作区、成员关系与命令选包](0082-decision-workspace-members-selection.md#resolution) 完成工作区和选包校验；
2. 解析所选包自己的插件来源和模块；
3. 校验插件入口、兼容性及 options；
4. 创建本次操作的私有派生视图；
5. 按固定生命周期阶段执行插件 hook；
6. 校验 substitute/drop/generated 的完整性和冲突；
7. 解析依赖并编译所选目标。

工作区操作可以先校验全部成员声明，但只有最终选中的包获取和执行插件。每个所选包只执行自己的插件一次：`build` 使用该视图构建该包全部程序，`run` 使用该视图但只编译所选程序及其依赖，`test` 使用该视图执行该包测试。依赖包插件不因依赖关系自动执行；批量命令按包分别生成派生视图和保存状态，某包失败即按工作区票的停止规则结束。

### 5. 组合示例与不支持项

以下是语义示例，不声称为最终 Jai 字面量：

```text
packages/juice-plugin-jaix/package.jai
  modules = [
    { name = "Jaix_Plugin_Test_Block", entry = "module.jai" },
    { name = "Jaix_Config_API",        entry = "api.jai" },
  ]

app/package.jai
  plugins = [{
    source = workspace,
    modules = [{ path = "packages/juice-plugin-jaix", name = "Jaix_Plugin_Test_Block" }],
    options = [{ key = "config", value = "config.jai" }],
  }]
  dependencies = [{
    name = "jaix-api",
    source = workspace,
    modules = [{ path = "packages/juice-plugin-jaix", name = "Jaix_Config_API" }],
  }]
```

| 场景 | 结果 |
|---|---|
| `plugins` 省略 | 启用 `load`、`test-block` |
| `plugins = []` | 不启用任何插件；不自动恢复默认转换 |
| 显式启用 lint 成员插件 | 只启用 lint；是否需要 `load`/`test-block` 由清单显式决定 |
| 同一插件模块经插件项和普通依赖选择 | 重复实际模块，失败 |
| 插件包只有普通模块、无插件入口 | 插件能力缺失，失败 |
| 所选模块有两个插件入口 | 入口歧义，失败 |
| 插件生成文件但未登记 | 不进入编译，视为插件输出契约错误 |
| 两个插件生成同一路径 | 派生输出冲突，失败 |
| 插件试图新增 `executables` 或改写 `package.jai` | 不支持，失败 |
| 只有 schema、没有现存 `.jai` 根入口 | 包声明入口校验失败；先由外部脚本生成后再发现 |
| 外部 Git 插件写入共享检出 | 违反只读派生契约，失败 |
