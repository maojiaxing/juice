## Question

以 [包、模块与产物模型](0080-decision-package-products-defaults.md) 为前置；同级 [依赖解析决定](0081-decision-dependency-identity-sources.md#resolution) 已统一记录引用来源契约，不在此票暗定依赖覆盖。

既然工作区根可以不是包，怎样声明工作区、确定成员及根位置，并让 build/run/test 的默认操作对象与成员集合分离？

需定清纯工作区与带根包工作区在 package.jai 中的表达；members/exclude 的路径、模式、优先级及无效项错误；嵌套工作区和成员自带声明的处理；从根、成员目录或子目录调用命令时如何定位与选包；默认成员、显式全选/单选与多程序运行歧义的边界。共享设置或工作区依赖不应成为未声明的覆盖来源。

前置 [包、模块与产物模型的决定](0080-decision-package-products-defaults.md#resolution) 允许多程序与零公开产物，但没有规定默认运行首项。需明确多个程序是否允许默认运行名、缺少选择时的诊断，以及只有模块或测试用途、没有公开产物的合法包执行 build/run/test 时分别如何处理。不得把“声明合法”直接等同于每条命令都成功。

[依赖解析讨论](0081-decision-dependency-identity-sources.md) 已确认 workspace 来源的窄语义：以声明包所属工作区根定位，引用包须在成员集合中；普通 path 并存且无此成员约束。本票应提供稳定的所属根与成员集合，明确根包、嵌套、被 exclude 的包、成员子目录和脱离工作区后的归属判断；不得按命令 cwd 改变同一声明的引用，也不因成员关系隐式注入依赖。工作区内 Git 解析选择记录按声明包根目录隔离：成员对同一来源可以各自选择提交，更新不能交叉改写。全局对象内容缓存可以共享，但不决定成员的解析选择。依赖讨论第十二轮还要求传递依赖按发起解析的工程上下文隔离，不能用共享源码的物理包路径代替所属上下文。工作区如何批量选包不得合并成员原有的解析选择。依赖讨论第十三轮已确定消费工程移到或复制到新规范化根时采用新解析上下文，不自动继承或搬迁旧选择记录；改变命令 cwd 而根未变不触发该行为。成员选包必须沿用这一根身份规则，而不是另设按包名猜测的状态迁移。显式更新按选中的消费包上下文处理其完整直接/传递依赖图，不修改其他上下文；首版不提供单条依赖定向更新。本票的工作区批量操作须说明选中了哪些上下文，不能因共享缓存或成员关系扩大更新范围。

依赖讨论第十五轮已确认外部 Git 包的 workspace 归属查找限定于其所在检出，不借用最外层消费工程的工作区，不越过检出根。本票须把嵌套/成员发现算法应用于该提供方上下文，找不到合法归属时明确失败；检出内目录存在并不等于成员资格成立。Git 包通过内部 path 引用同检出的兄弟包不要求成员资格，但仍保留仓库/提交身份并禁止越出检出；本票的成员算法不能把这种引用隐式改为 workspace。完整依赖规则及失败表以依赖票 Resolution 为准。

完成条件：用目录树加命令表覆盖根包、纯工作区、成员、被排除目录与歧义输入，每个输入得到明确对象或错误。只定语义与必要命令契约，不实施 CLI。

## Comments

### 第一轮：声明、成员范围与默认运行

用户答复：`q1 包与工作区共存， q2 按照建议 q3 按照建议 q4 按照建议 q5 按照建议`。

已确认：

- 同一份 `package.jai` 可以同时包含包与工作区声明。此答复没有撤回地图及前置决定中“纯工作区可以没有根包”的前提；具体 Jai 声明写法交声明校验票。
- `members` 接受相对工作区根的包目录及 `packages/*` 这样的单层通配；首版不支持递归 `**`。`exclude` 使用相同匹配规则，从候选成员中排除目录；最终成员必须有有效 `package.jai`。依赖关系不自动增加成员。匹配语法细节、无匹配、重复与失败处理仍待后续轮次决定。

- 支持包级默认运行程序名。单程序可直接运行；多程序使用声明的默认项，没有默认项则要求显式选择并报告候选。无效默认名报错，不按清单顺序选择，也不保留当前实现中“多程序时选择与包同名程序”的隐式规则。具体字段和 CLI 拼写尚未决定。

### 第三轮：默认选择、CLI、零程序包与批量执行

## Resolution

本票经用户四轮确认（Q1–Q23）完成。下列内容是后续票的统一输入；仅完成语义决定，未实现 CLI 或修改生产代码。具体 Jai 类型、名称与路径比较算法由 [声明表达与校验契约](0084-decision-declaration-evaluation-validation.md) 落实，生成入口的阶段规则由 [插件与构建定制分工](0083-decision-plugins-build-customization.md) 落实。

### 1. 声明与组织范围

- 同一个 `package.jai` 可以只声明包、只声明工作区，或同时声明二者。工作区不必伪造包身份或公开产物；包和工作区共存不使二者成为同一个概念。
- 工作区负责成员组织及默认选包；本轮不增加工作区级依赖、插件、构建设置继承或隐式覆盖。
- 根目录有包且声明工作区时，根包自动是成员；无须重复列出 `"."`，重复命中按包目录去重，不能排除根包。纯工作区没有根包，不能以 `"."` 伪造成员。
- members 省略或 `[]` 均为零个显式成员；带根包工作区仍含根包，纯工作区可以为空。合法空工作区不意味着操作零个包的命令成功。
- 不同目录的成员可以同名。成员关系不产生依赖，不改变已声明的 path/git/workspace 来源，也不自动启用插件。

### 2. 成员展开、排除与默认成员

| 配置 | 契约 |
|---|---|
| `members` | 相对工作区根的明确目录或含单层 `*` 的目录模式；`*` 不跨目录分隔符，不支持 `**` 或其他通配语法 |
| `exclude` | 相同路径及匹配规则；命中的目录及其子树中的候选成员均排除，未匹配允许 |
| `default_members` | 相对工作区根的明确成员包目录，不支持通配；省略、非空清单、显式空清单有不同选包含义 |

成员集合按下列顺序确定：

1. 解析工作区根内的相对目录/模式；拒绝绝对路径和规范化后越界。members 明确目录不存在、不是目录或通配没有匹配目录，均失败，不能以 exclude 消除这类输入错误。
2. 展开候选目录，再应用 exclude。被排除候选不要求作为本工作区成员通过包声明校验；exclude 命中根包则失败。
3. 保留目录必须具有有效包声明，纯工作区目录不能冒充包。按规范化包目录去重，再加入隐含根包。
4. 检查唯一工作区归属。外层规则命中独立内层工作区或其成员，且未被 exclude 排除时失败；不会自动展开内层工作区或静默跳过它。
5. 校验 default_members 的每个目录都是最终成员。显式清单决定根调用的默认选择，显式空清单不回退。

exclude 排除的是成员资格，不删除目录，也不让被排除包成为父包测试的一部分。符号链接、平台分隔符、大小写与 Unicode 的规范化/比较算法交声明校验票；不得通过别名路径绕过包含关系或唯一归属。

### 3. 调用定位与工作区归属

1. 从命令 cwd 向上查找最近的 `package.jai`，确定当前包或纯工作区。遇到无效声明立即失败，不跳过它继续寻找；找不到声明则报告无法定位。
2. 对包，从包位置（含本目录）找最近的工作区声明。包须在该工作区最终成员集合中才归属于它；未列入或被排除时作为独立包，不继续寻找更外层工作区。
3. 包自己声明工作区时，其自身是该工作区的根包；内层工作区独立于外层，任何包至多归属一个工作区。外层不得再次纳入内层根包或成员。
4. 成员源码子目录调用仍定位到该成员；没有更近包/工作区声明的根下子目录沿用根调用规则。被排除包自己的子目录仍定位到该独立包。
5. workspace 依赖按声明包的所属工作区解析，不能按调用 cwd 或最外层消费工程重新解释。无合法所属工作区或所选提供方不具成员资格时失败，不降级为 path。
6. 外部 Git 包的归属查找限定在其来源检出内，不能越过检出根；内层工作区规则同样适用。内部 path 可引用同检出非成员包，但仍保留 Git 仓库/提交身份和检出包含约束。

工作区归属与依赖解析上下文不同：每个被选消费包保留自身上下文；同包只改变 cwd 不改变上下文，移动到新规范化包根则是新上下文，不自动继承原解析状态。其完整依赖语义仍以 [依赖解析决定](0081-decision-dependency-identity-sources.md#resolution) 为准。

### 4. 默认与显式选包

| 调用位置，无显式选择参数 | 默认对象 |
|---|---|
| 独立包及其子目录 | 当前包 |
| 非根成员及其子目录 | 当前成员，不套用工作区 default_members |
| 带根包工作区根及其未进入其他包的子目录 | 配置的 default_members；省略时仅根包 |
| 纯工作区根及其未进入其他包的子目录 | 配置的 default_members；省略时全部成员 |

在根调用中，default_members 显式空清单表示没有默认选择，必须显式选包。所有命令最终选择零包均失败；run 最终选择多包也失败，即使其中只有一个包有可执行程序。

| 参数 | 含义 |
|---|---|
| `--workspace` | 当前所属工作区全部成员，含根包；没有工作区则失败 |
| `-p NAME` / `--package NAME` | 在当前工作区按唯一包名选择；同名歧义列出成员路径，不按声明顺序取首项 |
| `--package-path PATH` | 按相对当前工作区根的包目录选择，不能借此选择非成员或跨入内层工作区 |

- 显式选择覆盖默认选择。名字与路径参数可重复、可混用，按同一包身份去重；`--workspace` 与二者互斥。
- 在独立包中，名字只能指当前包，路径以当前包根为基准且只能指该包；不能借选择参数扩大成兄弟目录操作。需要操作独立兄弟包时在其位置定位。
- 在成员子目录调用，`--package-path` 仍相对所属工作区根，而非 cwd。相对路径不能规范化到工作区外。
- run 选择去重后必须恰好一包，之后才选择程序；包名、成员路径和程序名分工明确。

### 5. 命令与零产物行为

| 命令 | 所选包上的行为 |
|---|---|
| `build` | 构建包内全部可执行程序；零程序时仍校验声明与依赖，成功提示“无可执行产物”，不单独编译模块源码 |
| `run [PROGRAM] -- [ARGS...]` | 显式 PROGRAM 选择该包程序；省略时采用下述默认规则；只构建所选程序及其所需依赖，`--` 后原样传给程序 |
| `test [PATTERN]` | 发现并执行该包测试，PATTERN 为可选过滤条件；不要求有公开模块或程序 |
| `update` | 刷新所选消费包上下文的完整直接/传递 Git 依赖图，不编译或运行测试，不提供单条依赖定向更新 |

包级 `default_run` 指定程序名：没有显式 PROGRAM 时，有合法 default_run 就采用；否则零程序失败、唯一程序自动选择、多程序报告歧义及候选。无效 default_run 是声明错误，即使有显式 PROGRAM 也不能掩盖；不按程序清单顺序或包名暗定默认程序。

build/run/test 支持 `--offline`，使用依赖票的状态与缓存规则；update 与 --offline 冲突并在执行前报错。普通命令不追新已选 Git 修订；update 也不改变完整提交哈希所代表的提交。

声明合法但无公开产物的包仍可有测试；没有测试或过滤后没有匹配项均成功报告 0 项。build 成功不承诺未被编译的模块已经通过类型检查。过滤及零程序/零测试不能掩盖声明、依赖或实际编译错误。

### 6. 校验、批量执行与状态隔离

- 工作区操作先校验成员集合及所有成员的声明，包括 default_members、名称和入口等声明约束，然后校验完整选包结果和命令基数/冲突；上述失败均发生在逐包执行之前。
- 未选成员的声明错误会阻止工作区命令；未选成员的远程依赖不可取得不会单独阻止本次操作。但若该成员作为所选包的依赖参与本次依赖图，其依赖仍须正常解析。
- 被排除包不参与该工作区的成员声明校验。生成入口不能通过放松普通入口规则绕过检查，其显式渠道和时机由构建定制票决定。
- 按工作区相对包目录稳定排序，逐包执行，首个失败即停止且整体失败，已成功包不回滚。批量执行的失败必须明确指出所属包，不冒称剩余包已完成。
- update 逐个消费包上下文刷新完整依赖图。每个上下文只有整图解析校验成功才整体保存；当前上下文失败保留其旧选择但操作失败，此前成功上下文保持更新结果。
- 不因工作区成员关系或共享内容缓存合并解析选择。选择 A 的更新即使遍历依赖 B，也只修改 A 上下文，不改 B 作为独立消费包的选择记录；只有 B 也被显式/默认选中时才另行更新 B 上下文。
- 路径排序与源码依赖关系不同，不将成员批量顺序变成通用构建图；各包的依赖按已有依赖图规则准备。

### 7. 测试包边界与汇总

- 测试扫描属于当前所选包。遇到下级目录中的 `package.jai`，即停止进入该目录及其子树，不要求该目录已登记为成员。
- 因而父包不会收集成员、被排除包、未登记包、嵌套工作区或其成员的测试；扫描边界无需把那些包自动纳为测试对象。
- test --workspace 对最终选中成员逐包执行，每个包一次；依赖包测试不会因依赖关系自动运行。
- 同一个 PATTERN 应用于全部所选包，各包分别报告结果并汇总；单包及整体零匹配均成功。若中途失败，仍遵守停止规则并说明已完成和未执行范围。

### 8. 目录树与组合验收

以下均为语义示例，不声称是已经实现或编译通过的 Jai 配置。repo 根包名为 suite，工作区 members 为 `["apps/*", "libs/*", "scratch"]`，exclude 为 `["apps/lab", "scratch"]`，default_members 省略；因此外层成员为根包及 editor、tools、codec、helper-a、helper-b 六个包。

```text
repo/
  package.jai                 包 suite + 工作区；唯一程序 suite
  docs/                       无独立声明
  apps/
    editor/
      package.jai             包 editor；唯一程序 edit
      src/
    tools/
      package.jai             包 tools；程序 admin、serve；default_run = admin
    lab/
      package.jai             纯内层工作区；members = ["packages/*"]
      packages/demo/
        package.jai           包 demo；唯一程序 demo
  libs/
    codec/package.jai         包 codec；只有导入模块
    helper-a/package.jai      包 helper；零公开产物，无测试
    helper-b/package.jai      包 helper；零公开产物，有 parser 测试
  scratch/
    package.jai               包 scratch；被外层排除，独立包
```

未单列错误的行假设所有声明及执行输入有效。

| cwd / 变化 | 命令或输入 | 明确对象或错误 |
|---|---|---|
| repo 或 repo/docs | `build` | 只选 suite，构建其程序 |
| repo/apps/editor/src | `build` | 只选 editor |
| repo/apps/editor/src | `build --package-path apps/tools` | 选 tools；路径不相对 editor/src |
| repo | `test --workspace parser` | 六个包各测一次；根扫描不重复子包测试，不包含 lab/demo 或 scratch；零匹配包报告 0 |
| repo | `run -p tools` | 运行 admin |
| repo | `run -p tools serve -- --port 8080` | 只构建并运行 serve，参数原样传入 |
| repo，删除 tools 的 default_run | `run -p tools` | 多程序歧义，不因程序名与包名相同而推断 |
| repo，tools 的 default_run 指向不存在程序 | `run -p tools serve` | 无效默认项属于声明错误，显式选择不掩盖 |
| repo | `run --workspace` | 多包错误，不筛掉无程序包 |
| repo | `build -p helper` | 同名歧义，列出 libs/helper-a 与 libs/helper-b |
| repo | `test --package-path libs/helper-a` | 选一个合法零产物包，0 测试成功 |
| repo | `build -p codec` / `run -p codec` | 前者校验依赖后提示无程序，后者失败 |
| repo | `build -p editor --package-path apps/editor` | 去重后只构建 editor 一次 |
| repo | `build --workspace -p editor` | 选择参数互斥，执行前失败 |
| repo | `build -p unknown` / `build --package-path missing` | 无匹配包，执行前失败 |
| repo | `build --package-path scratch` | 被排除，非成员，失败 |
| repo/scratch 或其源码子目录 | `build` | 独立包 scratch；不套用外层 default_members |
| repo/scratch | `build --workspace` | 无所属工作区，失败 |
| scratch 声明 workspace 依赖 | 任意需要解析该依赖的操作 | 缺所属工作区失败，不回退为 path |
| repo/apps/lab | `build` | 纯工作区默认选全部内层成员，此例只选 demo |
| repo | `build --package-path apps/lab/packages/demo` | 不能跨入内层成员，失败 |
| 外层删除 exclude 中 apps/lab | 任意外层工作区命令 | 外层成员候选命中内层工作区，执行前失败 |
| 外层明确列出 apps/lab/packages/demo，且不排除 | 任意外层工作区命令 | 同样拒绝跨工作区归属 |
| 外层 default_members = ["apps/editor", "apps/tools"] | 根 `build` / 根 `run` | build 选择两包；run 多包错误 |
| 同上，在 editor/src | `build` | 仍只选 editor |
| 外层 default_members = [] | 根 `build` / 根 `build -p editor` | 前者无默认对象失败，后者显式选择成功 |
| 独立纯工作区，members 省略或 [] | `build` / `test --workspace` | 声明合法，命令选择零包失败，不报告 0 测试成功 |
| 纯工作区 members 或 default_members 包含 "." | 声明校验 | 根没有包，失败 |
| 带根包工作区 members 包含 "." 多次 | 声明校验 | 与隐含根包去重 |
| 带根包工作区 exclude 包含 "." | 声明校验 | 不能排除根包，失败 |
| members = ["missing"] 或无匹配模式 | 成员展开 | 失败，不静默空集 |
| exclude 命中目录但没有候选成员；或完全无匹配 | 成员展开 | 允许，不增加成员 |
| members 匹配无 package.jai 的目录 | 未排除 / 已排除 | 保留候选失败；排除后不要求是成员包 |
| members/exclude/default_members 使用绝对或越界路径 | 声明校验 | 失败 |
| cwd 最近 package.jai 无效 | 任意命令 | 失败，不退回上层有效声明 |
| 未选成员声明无效 | `build -p editor` | 整个工作区声明校验失败 |
| 未选且不在 editor 依赖图的成员远程依赖离线不可取得 | `build -p editor --offline` | 不因该无关依赖失败；editor 自己的图仍须满足离线规则 |
| repo | `update -p editor` | 只保存 editor 上下文的完整依赖选择，不改 tools 等上下文 |
| repo | `update --workspace`，途中一个上下文失败 | 整体失败并停止；此前成功状态保留，当前失败上下文保留旧状态，后续未执行 |
| repo | `update --offline` | 参数冲突，执行前失败 |
| repo | `test --workspace no-such-test`，声明/依赖/编译均有效 | 所选包均报告 0，整体成功 |
| 根下新加入未登记的 other/package.jai | 根 `test` | 不进入 other 子树；不因此自动测试 other |
| 提供方 Git 检出包含内层工作区 | 提供方成员使用 workspace 依赖 | 使用检出内最近合法归属，不借消费工程成员 |
| 提供方 Git 检出无合法工作区归属 | 提供方使用 workspace 依赖 | 失败，查找不越检出根；同检出合法 path 不要求成员资格 |

### 9. 后续交接与完成边界

- [插件依赖、启用顺序与构建定制的声明边界](0083-decision-plugins-build-customization.md)：插件仍由包声明；需在整工作区声明校验、仅所选包执行的顺序中安放插件获取/启用和生成入口检查，并保留按消费包隔离的派生内容。不能因校验未选成员而自动执行其构建流程。
- [Jai 声明表达、默认值与校验契约](0084-decision-declaration-evaluation-validation.md)：表达可独立/共存的包与工作区、default_members 省略/空/非空、default_run、全工作区声明校验阶段；落实路径、简单通配、包含关系、成员去重/名字歧义和稳定排序算法。测试子包边界与来源检出边界不能混淆。
- [声明迁移、典型示例与规格交接标准](0085-decision-declaration-migration-handoff.md)：将本票目录树与命令表纳入迁移验收，覆盖当前 cwd-only 定位、未应用 exclude、无显式选包、run 包同名回退及先 build 全部程序等行为的替换；不把语义示例冒称当前 CLI 已支持。

上述表达、生成和迁移工作均由已有子票承接，没有本票范围内尚需新增的决策票。本票不实施扫描器、CLI、求值器、缓存或另一张测试迁移地图；本会话仅关闭本张非研究票。
