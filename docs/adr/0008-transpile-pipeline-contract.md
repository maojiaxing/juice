# 0008: 转译管线契约——注册表驱动管线 + ADR 0005 硬约束 runner 强制 + Package 配置面注册

juice 自身 Transpile 从「单扫描循环内硬编码 `#load` 与 test 锚点两分支」升级为注册表驱动的管线（spec 0060）：test block 与 `#load` 处理成为前两个内置插件，扫描循环升级为管线 runner——新的转换以后只写插件、不改核心。ADR 0005 的「1 行换 1 行、编辑以 token 为界」从排版规范升级为 runner 对每个插件的强制门——行号保真从此不依赖插件作者自觉，违反形状的插件在转译期响亮失败。插件注册获得第二个面：包作者在 Package 配置（package.jai）声明自己的转译管线（jaix 风格：插件 id + version + 类型化选项槽），声明序 = 管线序；未声明 = 缺省管线（现状行为零变化）。这是 ADR 0004 进程内义务转译的机制续篇，与 ADR 0007 的 jaix 前置并存不替代。

**决定**：

1. **注册表驱动管线**：`transpile_source` 的扫描循环保留为管线 runner（深度 + 语句位置 + 编辑收集骨架不动），`#load` 分支与 test 锚点分支改为向注册插件按声明序派发。插件接口 = {name, version, 模式适用性声明（STRIP/EXPAND）, 探测钩子成对（has_anchor / 可选 load_edges）, 转译钩子（扫描位点回调 → Edit/清单条目/诊断）, 跨文件状态经 Transpile_Context 扩展字段}。空注册表 = 缺省管线（[load, test-block]——旧硬编码分支序精确复现），既有调用方零改动。区域交互契约在 runner 层显式化：test 插件 EXPAND 声明替换头行后游标进体不消费体，runner 继续向其余插件派发（test 体内 `#load` 仍被剥离）；STRIP 声明消费整块至闭括号（体内 token 永不再派发，test 体内 `#load` 随占位消失）。
2. **ADR 0005 硬约束由 runner 强制**：每条编辑须「1 行换 1 行」（等行数展开——多行 test 头拒绝的一般形式）且「以 token 为界」（起点与终点各落在某 token 的起点或终点边界——`@test` 零宽插入坐落在闭括号 token 终点边界的先例）；违反编辑丢弃 + 诊断拒绝（「编辑违反行号保真：等行数展开失败」/「编辑未以 token 为界」）。行号保真从「内置转译的排版规范」升级为「任何插件共担的硬契约」——未来插件违反形状（重排版、头部注记、非等行展开）在转译期响亮失败，不静默漂移。
3. **闭包探测走管线聚合**：closure_has_tests / probe_package_closure 改为管线聚合版本（has_anchor 聚合 + load_edges 聚合），探测函数不再硬编码两转换；test-free 闭包零转译短路（ADR 0004 决定 1）语义不变。
4. **缓存键含管线描述**：视图缓存键增管线描述分量（有序 name+version 序列——声明序 = 管线序）；JUICE_VERSION 语义泛化为「管线输出契约版本」——插件版本 bump 即键变、管线变化精准失效视图；load 重写表嵌入与 Merkle 链性质不变。视图与其键恒反映同一管线（resolve_pipeline 单一落点——键从不与产视图的管线失配）。
5. **Package 配置面注册**：Package 声明面新增管线字段（插件 id + version + 类型化选项槽）；manifest 求值器按声明序打印 `TRANSPILE_PLUGIN=<id>|<version>` 可重复协议记录（JAIX_CONFIG 同族：恒打印、选项不跨进程）；纯函数校验门（未知 id / 重复 id / 非法选项 = 诊断拒绝）；声明序 = 管线序；未声明 = 缺省管线——现状行为零变化。显式声明两内置插件（缺省序）与未声明同值（视图与缓存键逐字节同值）。
6. **进程内、锚点级文本管线**：juice 管线保持锚点级文本编辑契约（行号保真、bootstrap 自足、零依赖），不采用 jaix 的 AST 插件模型（ADR 0007 并存不替代不变）。

**Considered Options**: (a) 静态注册表（编译期固定管线、无包作者声明面）——否决：包作者无法声明自己的管线，管线组成继续隐式存在于扫描实现里（spec 0060 Problem 3）；静态注册表保留为机制底座（缺省 = 内置两插件），Package 配置面叠加其上。(b) 第三方插件宿主（研究 B 3.3：动态库 / 独立进程 filter / 编译期 `-plug`）——defer：机制先行、宿主选择留后续（spec 0060 决定 1 用户拍板），本 ADR 的插件接口与强制门对未来宿主保持中立。(c) 采用 jaix 插件模型（整树 AST 变换）——否决：并存不替代（CONTEXT.md 已立），juice 管线 = 锚点级文本编辑、jaix = 整树 AST 变换，两系统契约不同。

**Consequences**: 视图与其键随管线声明而变——driver.jai 金样内嵌键哈希会随键变重定（0062 偏差 1）；依赖视图与 Testing 模块视图恒走缺省管线（依赖声明面与 Testing 模块语义解耦——0063 偏差 1/2）；声明 version 不校验、不进键（v1 按 id 解析到内置注册表实例，版本选择语义与选项面同留后续——0063 偏差 3）；v1 内置插件选项集为空（类型化选项槽就位、无实际选项行——0063 偏差 4）；未来任何插件若无法等行数展开即被 runner 拒绝（ADR 0005 的硬约束从此由机制而非规范承载）；合法 test 语法依赖转译存在不变（ADR 0004）。
