## Problem Statement

阶段 2 已让 otter 自构建自测（`jai build.jai` 两模式产出 exe + 三份发布物，产物于根 build/test 全绿），但 effort 仍停在自举窗口里，目的地尚未成立：

1. **旧 juice 仍在开发循环内**：每次验收仍以旧 juice 不变式（debug+release 4/4）为权威；测试套件仍直接读旧 juice 仓（module 测试经 `bootstrap_juice_modules_dir` 指向兄弟仓 `../juice/modules` 做两代 Testing 面对拍）。任何声称"已完成"的验收都还依赖旧工具存在。
2. **note-based test 接管不是最终形态**：
   - 普通用户包（老 juice 写法：`#import "Testing"` + 裸 `expect`）的门禁是坏的。实测（2026-10-20，临时 BIN 包，一个失败断言 + 一个通过断言）：产物 exe `test` 打印 `expect failed`，但汇总 `2 passed, 0 failed`、exit 0。runner 驱动 prefixed 寄存器，测试体写发布裸名寄存器——033 修好的根包门禁未覆盖非 face-discovered 包，spec §7.5 的"存量 juice 套件零改写"对真实用户包不成立。
   - otter 自身套件仍全部是 test 块（阶段 0-2 写法约束），手写 `@test` 从未在本仓套件中实际使用。
   - test 命令的发现面源码仍靠 `<exe>/../src` 推导（033 标注 stage 3 退役）——exe 离开源码树布局就不能跑测试。
3. **最终验收口径未钉死**：直跑 `target/juice.exe test` 有 2 条响亮的自锁 SKIP（自构建 E2E）；"全绿"到底以直跑还是副本跑为准，尚未成文。
4. **收尾面不存在**：没有退场声明；spec §0-11 没有逐节覆盖对照；§11 风险没有逐项处置；map 的 Not yet specified 未清空。

## Solution

阶段 3 = 终点收口与旧 juice 退场，一次把开发循环切到产品自身：

- **开发循环 = `jai build.jai`（debug/release）→ 产物于根 build/test**。旧 juice 不再被任何 build/test/E2E 路径调用或读取；最终权威验收用产物副本跑（SKIP 0、全 E2E 覆盖），直跑产物记录为 SKIP 2 的环境条件形态。
- **单一断言寄存器 = 发布 Testing 面**：所有测试程序（根包、fixture、用户包）统一 `#import "Testing"` 走 t9 编译视图，注入 runner 一律驱动裸名（`run`/`finish`/`path_mapping`）。prefixed 源面加载路径（`testing_face_source`/`testing_face_strip_view`）退役；fixture 族迁移到裸名，成为真实用户包的代表。失败断言必然计入 finish 并造成 exit 1。
- **发现面源码随 exe 发布**：发布步骤增第四份内部件（`<modules_dir>/juice_internal/test_discovery.jai`，逐字复制）；`discovery_face_source` 从 `<exe>/modules` 推导，`<exe>/../src` 推导退役。dev 树与安装布局同一路径契约。
- **note-based 最终形态**：套件新增手写 `@test`（与存量 test 块同一发现源、同一编号/排序）；存量 test 块零改写；阶段 0-2 的"只写 test 块"约束在文档中退役。
- **退场声明与收尾**：新增带日期的退场声明文档，记录验收矩阵、spec §0-11 逐节覆盖对照、§11 风险逐项处置、残留历史引用政策与旧仓处置边界；spec §9/§10/§7.5/§0 折回执行级事实；map Not yet specified 清空为"未来票记录"；map 收口。

用户拍板（2026-10-20）：**三接缝**（自举循环 / 姊妹测试 / E2E 真子进程）；**裸名门禁修复 + 全面裸面**（fixture 迁移、prefixed 源面退役）；**发现面源码 = 第四份内部发布物**；**副本跑零 SKIP 为权威验收**。

## User Stories

3. As an otter developer, I want the authoritative acceptance run to use a target/ copy of the artifact, so the full suite (including the self-build E2E) runs with zero SKIPs.
4. As an otter developer, I want the direct artifact run's two self-lock SKIPs documented as an environment-conditional form, so the reduced coverage is explicit and never mistaken for the final run.
5. As an otter developer, I want no build, test, or E2E path to read the sibling old-juice repository, so the suite is self-contained.
6. As an otter developer, I want the old-juice two-generation Testing-face comparison retired and replaced by published-face-only coverage, so the last old-repo dependency disappears.
7. As a juice user, I want an old-juice-style package (`#import "Testing"` plus bare `expect`) that has a failing assertion to report the failure in the summary and exit nonzero, so the zero-rewrite promise actually holds.
8. As a juice user, I want a passing bare-name suite to exit 0 with the expected counts, so the fixed gate is not over-strict.
9. As an otter developer, I want every test program to import the published Testing face and drive it through one bare-name register, so assertions and the finish gate can never split again.

## Implementation Decisions

1. **阶段 3 范围（用户拍板 2026-10-20）**：三接缝（自举循环 / 姊妹测试 / E2E 真子进程）；裸名门禁修复 + 全面裸面；发现面源码 = 第四份内部发布物；副本跑零 SKIP 为权威验收。
2. **单一断言寄存器 = 发布 Testing 面**：测试 driver 对所有包一律 `#import "Testing"`（t9 编译视图在 import 路径上解析到发布平铺面；in-package `modules/Testing.jai` 仍走 EXPAND 视图）；注入 runner 一律发射裸名 `run`/`finish`/`path_mapping`。`testing_source` 显式源面加载、`face_is_discovered` 面选择、`import_testing_face`/`runner_bare_face` 双形态收敛为单一形态（033 的默认字节锁随票更新）。根包的 prefixed 自测块仍由 src 定义源提供声明，属定义源内部面，不参与外层 runner 门禁（白名单现状）。
3. **prefixed 源面路径退役**：`testing_face_source` 与 `testing_face_strip_view` 删除；fixture 族（11 文件、24 处调用——15 处迁移为裸名 + 9 处删除 prefixed 腿；原 26 行 grep 含 2 行注释/定义）迁移为裸名 `expect`/`expect_eq`/`fail`。`testing-face` fixture 家族的两代对拍改为发布面单面场景；`bootstrap_juice_modules_dir` 及其 module 测试对拍腿退役。prefixed 名仍是 `src/module.jai` 的定义源公开名（发布转换的输入），其单元测试保留。
4. **发现面源码 = 第四份内部发布物**：发布步骤逐字复制 `src/test_discovery.jai` 到 `<modules_dir>/juice_internal/test_discovery.jai`（`juice_internal/` 是私有目录契约：只被生成的测试 metaprogram 以绝对路径 `#load`，不发布为公开 import 面；编译器导入路径仍可见该目录，非强制不可导入）。`discovery_face_source` 改为从 `juice_modules_dir()`（`<exe>/modules`）推导；`bootstrap_src_dir` 与 `<exe>/../src` 推导删除。发布仍为先发布后编译、每跑重生、失败响亮；spec §9 的"三份发布物"随之订正为"三份模块面 + 一份内部源件"。
5. **发布单源纪律**：第四份件是源文件的逐字复制（无变换），测试以逐字节相等钉死；源缺失/不可读 = 发布失败 exit 1。发布步骤与三份模块面共用同一入口与落点助手族。
6. **note-based 最终形态**：套件新增手写 `@test` 过程（建议独立姊妹测试文件，即新测试面），使用发布裸名断言；存量 test 块零改写。混合来源共享全局编号基 1 与确定性排序（`juice_test_N` 数值感知 + 其余名字典序）。`@test(custom_name)` 被发现但显示名仍为过程名（显示名恢复 = 未来票）。"Found N tests" 打印仍不产（发现源在 metaprogram）。
7. **阶段 0-2 写法约束退役**：map Notes 中"阶段 0-2 全部用 test 块"改为历史说明；阶段 3 起新测试可手写 `@test`。
8. **自锁验收口径**：权威最终验收 = 把产物复制到 target/ 内（同 `<exe>/modules` 推导），以副本于根跑 `build` 与 `test`——SKIP 0、自构建 E2E 全跑。直跑 `target/juice.exe test` 仍受 2 条自锁 SKIP（bootstrap 无 hand-off，005 决定 10），作为环境条件形态记录在验收矩阵，不作为权威数。
9. **旧 juice 退场边界**：任何 build/test/E2E 路径不调用旧 juice、不读兄弟仓；旧 juice 仓保持零改动、只读。research 文档与源码锚点中的历史引用保留为"参考来源"，不是运行依赖。旧仓处置（归档/仓库替换/发布迁移）仍为 map 出范围，归独立 effort。
10. **退场声明形态**：新增带日期的独立文档 `docs/implementation/old-juice-exit.md`，内容 = 退场条件与生效日期、新循环的规范命令、最终验收矩阵、spec §0-11 覆盖对照、§11 风险处置表、残留历史引用政策、旧仓处置边界。map 与 spec 链接该文档。
11. **spec §0-11 覆盖对照**：逐节标注状态——已交付 / 执行级订正后交付 / 未来票 / 出范围；未来票清单 = jaix PRESTEP 全链、at 其余 9 个生命周期挂载点机械接线（`test dep_transpile` 已被 test TRANSPILE 阶段级 at 替换涵盖）、lint、真实第三方成员插件包、第三方插件全链路 E2E、test 显示名恢复；出范围 = §11.7 第三方宿主、§11.1 linkme、§11.8 未来特性、旧仓处置、兄弟项目。无未分类节。
12. **§11 风险复核**：逐项处置（note 机制 beta 绑定的精确匹配策略保留；`compiler_report_errors_for_untyped_declarations_with_these_notes` 仍零使用、spike 留未来票；at 替换缓存键语义已文档化；观察类诊断形状随 lint 未来票；阶段枚举只增不改 + 版本化注释；缓存键契约与 Windows 约束按既有记录）。结论写入退场声明。
13. **机械退场守卫**：新增姊妹测试扫描 `src/`、`tests/`、`build.jai`、`package.jai`，禁止出现旧 juice 仓路径引用（`../juice` / `juice/modules` 形态；docs/research 历史引用豁免）。守卫自身的针字符串需构造，避免自命中。
14. **验收矩阵（阶段 3 终态）**：
    - 接缝 1：`jai build.jai`（debug）与 `jai build.jai - release` 各 exit 0，产出 exe + 三份模块面 + 内部源件；副本于根 `build` exit 0、`test` exit 0、SKIP 0、白名单 6、无其他失败；直跑产物记录 SKIP 2。
    - 接缝 2：`tests/` 套件自足（零旧仓读取、机械守卫绿）、手写 `@test` 与 test 块混跑、既有 443 基线不回归、白名单 6 不变。
    - 接缝 3：真子进程 E2E——裸名失败用户包 exit 1 且汇总计入失败、原文行映射；裸名通过包 exit 0；test-blocks/test-dep/plugin fixture 族全绿；真 `jai` 跑 `build.jai` 两模式；发布物逐字节钉。
15. **基线计数**：阶段 3 起点 = 443 found / 258 executed / 白名单 6 / 直跑 SKIP 2。终态权威计数 = max `juice_test_N` + 手写 `@test` 条目（= 450 + 5 = 455）；otter `test` 不打印 "Found N tests"（017 起发现发生在 metaprogram 内），终局 `M passed` 因 Testing 自测 `finish()` 重置小于 found（既有约定，不是回归）；每票递增记录。
16. **公共兼容面不动**：`package.jai` 作者面（Package 结构体形状）零改动；不新增 Package 字段；插件 API 面不变（`juice_core` 闭包不变）。
17. **文档折回**：spec §9（三份模块面 + 内部源件 + 转换形态）、§10 阶段 3 验收行（自举循环 + 副本零 SKIP + 旧 juice 退场）、§7.5（零改写对普通用户包的实证）、§0（发布物概述）、§11（处置结论）；map Notes/Decisions/Not yet specified 同步。

## Testing Decisions

- **好测试 = 只测外部行为**：退出码、stdout/stderr、产物存在与逐字节/逐行形状、生成文本的契约面、失败坐标映射；不测内部调用轨迹。门禁类修复必须用"真子进程 + 真退出码"证明，不用进程内替身。
- **接缝 1（自举循环）**：真 `jai` 跑 `build.jai` 两模式 + 产物副本跑根 build/test；这是最终验收的唯一权威面。直跑 SKIP 2 作为环境条件记录，不作权威。
- **接缝 2（姊妹测试）**：`tests/` 套件本身。新增/改写面 = 裸名门禁回归（失败断言计入 finish、exit 1、原文行）、发布第四件逐字节 + 缺失源失败、面选择收敛后的 driver/metaprogram 字节契约、手写 `@test` 与 test 块混合的发现/排序/编号、机械退场守卫。既有 443 基线不得回退。
- **接缝 3（E2E 真子进程）**：产物 exe 真跑 fixture 族（test-blocks、test-blocks-fail、test-dep 族、plugin fixture 良构/坏、build-with-tests）与裸名用户包；真 `jai` 跑 `build.jai`。先例：bootstrap 自构建 E2E、e2e_cli_tests、test 命令 fixture 族、plugin E2E。
- **门禁回归的核心用例**：临时 BIN 包（`#import "Testing"`、一个失败断言、一个通过断言）→ `expect failed` + 汇总计数含失败 + exit 1；通过的裸名包 → exit 0、计数正确。该用例覆盖 033 根包修复未覆盖的普通用户包路径。
- **白名单纪律**：预期 `expect failed` 白名单保持 6 行（module_tests 与定义源自测）；新增任何预期失败必须显式记录，不能靠套件汇总掩盖。
- **验收执行纪律**：各路径先清 `target/transpile`/`target/testing-module`；串行执行；证据落 `target/audit-*.txt`；权威计数 = max `juice_test_N` + 手写 `@test` 条目（"Found N tests" 不产）。

## Out of Scope

- jaix PRESTEP 全链（jaix_front 移植 + b6/t2 接线）；at 其余 9 个生命周期挂载点机械接线（`test dep_transpile` 已被 test TRANSPILE 阶段级 at 替换涵盖）；lint（§8.2）；真实第三方成员插件包（`packages/` 布局 + 插件声明面）；第三方插件全链路 E2E；test 显示名恢复（`@test("name")` 参数化发射）——全部归未来票记录（本 spec 只登记，不建票）。
- spec §11.7 第三方宿主（DLL/进程外）、§11.1 linkme 特性请求、§11.8 未来特性（glob members/exclude/--workspace 聚合/版本继承）。

- 兄弟项目（coroutines/packrat/testing/jaix/jaix-cli）不动。
